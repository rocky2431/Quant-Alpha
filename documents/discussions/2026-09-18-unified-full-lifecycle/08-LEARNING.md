# 08 学习：预测、骨架策略、完整 RL 与 LLM Agent

> **2026-09-18 当前讨论稿｜按 UNIFIED-PLAN v1 细化｜未批准实施。** [索引](README.md) · [总架构](ARCHITECTURE.md) · [MVP](MVP.md) · 上游：[07 融合](07-FUSION-SELECTION.md)、[06 候选](06-CANDIDATE-REGISTRY-FALSIFICATION.md) · 下游：[09 仿真与执行](09-SIMULATION-EXECUTION.md)、[10 验证](10-VALIDATION-GATES.md)

## 1. 目的与边界

从融合后的表示产生预测分布与完整交易决策，并能证明具体学习改变了什么。输入为 `FusionSpec`、`FeatureFrame`、`Candidate`、训练分区、环境/动作/奖励定义、初始化模型；输出 `TrainingRun`、`PolicyVersion`、预测、轨迹与可核对的训练产物。

三类模型各归其位，且分别记账：

- **预测模型**输出分布而非点估计；默认基线是线性加收缩与树模型；复杂模型须以经济显著幅度胜出。理由见 UNIFIED-PLAN §3.3 与 `../2026-09-18-unified-plan/evidence/02-academic-2023-2026.md` §B ✅🟡，本文不重论。
- **策略**默认是结构化骨架加少量可学参数：`policy = f_θ(structural_skeleton, state)`。骨架是解析解或规则式收敛策略；θ 只含风险厌恶、偏斜、执行比例、报价深度一类少量参数。这是默认不是禁令：完整数值 RL 策略与 LLM Agent 策略作为候选进入同一九关，与骨架策略同信息同预算比较。HRT 的预测与控制分离、RL 需要仿真环境的理由只引用（`evidence/01-institutions-2020-2026.md` §8 ✅），不重论。
- **LLM Agent RL 交易策略（配置 L）**是所有者裁定的交付项：真实 SFT 与 Agent RL 权重训练必须发生并留下产物；上线条件与其他策略相同，不获关键路径豁免。

本环节不决定阈值、不开 holdout、不裁决自己是否通过；这些属于 [10 验证](10-VALIDATION-GATES.md)。学习对象只能更新训练分区内的参数；预注册的更新规则 U 是被评价对象的一部分。

## 2. 对象与契约

### 2.1 `TrainingRun`

| 字段 | 内容 | 约束 |
|---|---|---|
| `run_id` / `candidate_id` / `track_id` | 关联键；`track_id` 取 A 或 B | 必填 |
| `learning_kind` | `supervised` / `sft` / `numeric_rl` / `llm_agent_rl` / `frozen_inference` | 声称哪种就提交对应产物 |
| `data_partition` | 训练/开发分区的 `dataset_version`、`event_cluster_id` 集合、时间边界 | 不含最终留出 |
| `inputs` | `FusionSpec` 版本、`FeatureFrame` 版本、`extractor_version` 集合 | 只用 `usable_at <= t` 的输入 |
| `init_weights` / `final_weights` | 初始 checkpoint 与训练后 checkpoint 的哈希与存储位置 | 二者不同才算发生更新 |
| `config` | 超参、种子、骨架类型、θ 参数清单、损失或奖励定义 | 版本化 |
| `reward_spec` | 奖励公式、成本口径、风险惩罚项、归一化 | 与 [09](09-SIMULATION-EXECUTION.md) 账本一致 |
| `update_rule_U` | 预注册的再训练/在线更新规则：触发条件、频率、标签成熟要求、允许改动的参数集 | U 变化即新 `candidate_id` |
| `budget_used` | GPU 小时、token、rollout 数、人工时 | 计入 `Candidate.data_budget` |
| `trial_index` | 本候选第几次试验 | 不得超过 `Candidate` 的试验次数上限 |

### 2.2 `PolicyVersion`

| 字段 | 内容 |
|---|---|
| `policy_version` / `run_id` / `track_id` | 关联键 |
| `policy_kind` | `skeleton_param` / `numeric_rl` / `llm_agent` / `rule_baseline` |
| `skeleton_ref` | 骨架名称与版本；`llm_agent` 时记录基础模型、chat template、工具 schema |
| `theta` | 可学参数的值与允许范围；`llm_agent` 时为 adapter 哈希 |
| `predictor_ref` | 依赖的预测模型版本；策略输入使用滚动样本外预测 |
| `action_space` | 允许动作清单与非法动作处理 |
| `update_rule_U` | 同 `TrainingRun` |
| `frozen` | 是否冻结版本与 U；冻结后只按 U 更新 |
| `latency_budget_ms` | 推理与工具调用的时间预算，超时行为 |

### 2.3 训练产物证据表

| 路径 | 实际更新什么 | 可称为完成训练的必要证据 |
|---|---|---|
| 普通监督/自监督 | 预测器或编码器权重 | 数据/目标、初始与最终模型、训练记录、滚动样本外输出、PIT/CRPS 独立记账 |
| SFT | 语言/工具策略的 LoRA 或全参数 | 示范来源与筛选规则、训练分区、loss mask 检查、adapter 哈希、留出任务表现 |
| 数值策略 RL | 骨架参数 θ 或完整策略网络 | 真实 rollout、状态动作奖励、优化记录、权重变化、同信息基线对照 |
| LLM Agent RL | 承担工具调用/交易决策的 LLM 参数 | 与真实工具轨迹对应的训练输入与奖励、可核对参数更新、同模型 SFT-only 对照、多 rollout 同起点同情景记录 |
| 固定 LLM 加研究记忆 | 提示、检索内容、研究记录 | 属于研究流程更新（[11](11-RESEARCH-FEEDBACK-AGENT-LOOP.md)）；不声称已训练 Agent 权重 |

## 3. 具体过程

1. **固定任务**：从 `Candidate` 与 [MVP](MVP.md) §3 取观察字段、动作能力、账户/奖励口径、分区用途；先确认奖励能由 [09](09-SIMULATION-EXECUTION.md) 的 `StepTrace` 重算。
2. **预测层**：按 `FusionSpec` 训练预测模型，输出分布；在训练分区内用滚动样本外方式生成预测，作为策略训练输入，避免"训练时先知、部署时噪声"。预测器指标（PIT、CRPS、条件 IC、按期限分层）与策略指标分离存储。
3. **骨架策略**：为每个 `Candidate` 配一个规则式或解析骨架；用优化或 RL 只调 θ，并保留优化记录。基线策略同样经过参数优化（[10](10-VALIDATION-GATES.md) G3 要求公平实现，不要求正期望）。
4. **完整数值 RL**（配置 N+）：在 T1 环境中采样连续轨迹，真实优化策略参数；记录等待、未成交、持仓风险、资金费、非法动作与实际执行动作。
5. **SFT**（配置 L 第一步）：选一个许可、工具模板与推理服务均合适的小模型；示范来自确定性可解场景、经验证的现有模型过程、负责人提供的主观机制，并保留无机会、错误关系、缺数据、拒绝交易与止损退出案例。每条样本包含当时可得观察、工具调用、真实工具输出、简短可验证依据、最终合法动作。用 TRL 加 PEFT 微调；先检查工具模板与 loss mask，不把工具返回值或未来标签当作要模仿的输出。
6. **Agent RL**（配置 L 第二步）：以 SFT 权重初始化，在同一环境执行多步任务：读取观察、选择查询或下单/等待、环境推进、继续决策、平仓或到期。用 Agent Lightning v1 把真实 Agent 轨迹接入 verl，初始尝试 GRPO；多个 rollout 从相同历史起点与账户开始、在相同外部情景下比较以控制方差。训练与推理固定同一 tokenizer、chat template、工具 schema 与模型版本，保存实际生成 token 与结果。
7. **奖励**：主要经济奖励为整个 episode 的成本后权益增量 `(E_T - E_0) / E_0`，`E` 为统一账户的保守可变现净值，已含费用、价差、滑点、资金费；密集反馈用同一净值的逐步增量，求和必须与终局一致；不奖励工具次数、文本长度或格式。整组奖励相同时检查任务难度与动作空间，不靠格式分制造进步。
8. **预注册更新规则 U**：在冻结前写明再训练触发、频率、标签成熟要求、允许更新的参数集；冻结后只按 U 更新；研究者看过评价后修改 U 即产生新 `candidate_id`，新版本不继承旧版本的实盘天数。
9. **开发比较**：在开发分区比较相同信息、风险、成本与预算的控制组（[MVP](MVP.md) §7 的 E0 到 E3）；训练曲线不替代经济评价。
10. **交付冻结**：冻结 `PolicyVersion`、`FusionSpec`、`FeatureSpec`、`extractor_version`、奖励、工具、动作转换与环境配置，交 [10](10-VALIDATION-GATES.md) 独立评价。

## 4. 双轨示例

以下数值均为假设，用于审查流程语义。

**轨道 A（BTC 永续，一小时任务）。** 预测模型为带收缩的线性回归加 LightGBM，输入订单流、资金费、市场状态桶与类型化语义字段，输出未来一小时收益的分位数分布，滚动样本外 CRPS 记录在 `TrainingRun`。骨架策略为"分位数阈值加库存约束"，θ 只含进入阈值、目标仓位缩放、退出滞后三个参数，用 200 次贝叶斯优化在训练分区选定并留下记录。配置 N+ 用 PPO 在同一 T1 环境训练完整策略，10 个种子。配置 L 用 3B 模型：SFT 示范 800 条（其中 150 条为"无机会/拒绝交易"），GRPO 每组 8 个 rollout 从同一小时起点开始；同模型 SFT-only 作为对照。三者共享 `FusionSpec` v3 与 `predictor_ref`，U 预注册为"每 7 个日历日在标签成熟后重训预测器，θ 不变"。

**轨道 B（HIP-3 某商品市场）。** 预测层不预测方向，只估计重开跳幅的条件分布与外部参考源健康概率。骨架策略为"按跳幅分层的收敛头寸加重开前预定撤出"，θ 含分层阈值、头寸缩放、撤出提前分钟数。数值 RL 只作对照，不进入 B 的首期交付。配置 L 不在 B 轨首期运行，因为 B 的工程工时上限为共享预算的 20%。U 预注册为"每个闭市周期结束后按新事件簇重估分层阈值，其余不变"。

## 5. 失败观测与处置

| 观测 | 候选原因 | 区分方法 | 返回环节 |
|---|---|---|---|
| 训练奖励上升，开发分区净收益下降 | 过拟合、模拟器漏洞、选择偏差、预测输入分布差异 | 滚动样本外预测替换训练期预测；G5 假发现率；对照模拟器一致性 | 07/08/09/10 |
| 策略总是空仓 | 合理放弃，或奖励/探索问题 | 同信息机会与风险对照；检查非法动作率 | 08/06 |
| 大量动作被风险层改写 | 动作空间或约束学习问题 | 改写前后轨迹对比；不能只展示改写后结果 | 08/09 |
| LLM Agent 解释正确但动作过晚 | 推理与工具延迟超过机会生命周期 | `decided_at - observed_at` 分布与 `latency_budget_ms` | 08/09 |
| SFT 后模型只学会格式 | loss mask 或示范筛选错误 | 留出任务上的动作正确率与工具正确率分开报 | 08 |
| GRPO 整组奖励相同 | 任务过易/过难，或动作空间退化 | 检查 rollout 多样性与环境难度，不加格式分 | 08/09 |
| 历史成交无法覆盖新动作 | 离线 RL 分布外行动 | 限定动作集或使用 T1 反事实成交假设并标注 | 08/09 |
| 更新规则 U 修改后实盘天数被合并 | 版本归属错误 | 新 `candidate_id`，天数分别计 | 08/12 |
| 复杂模型胜出但只在一个事件簇 | 状态拟合 | 按 `event_cluster_id` 分组评价 | 07/10 |

|---|---|---|---|---|

## 7. 分阶段能力与证据

| 阶段 | 本环节实质内容 | 验证与推进条件 |
|---|---|---|
| 最小 MVP（对应 10 月 15 日改约交付） | 两轨预测模型基线与滚动样本外输出；两轨自适应骨架基线经参数优化并在 T1 评价；配置 N+ 与 L 的训练入口接通并完成短训练吞吐实测（GPU 显存、每小时有效 episode、token 成本）；`TrainingRun`/`PolicyVersion` 契约落地 | 更新对象与产物一致；基线可复现；短训练证明连接而非只证明 GPU 有负载；训练后策略不上实盘 |
| 第二步：针对失败补强 | 针对具体误差更改观察、目标、约束、训练或骨架；需要语义能力时补 SFT；配置 L 完成真实 SFT 加 RL 与 SFT-only 对照 | 区分实验支持原因；修改效果在后续开发窗口成立；不默认扩大网络 |
| 第三步：跨状态与运行验证 | 检验标签延迟、漂移、按 U 的预定再训练、实时推理与跨事件簇稳定性；完整 RL 与 LLM Agent 相对骨架的增量在 G4 到 G6 上报告 | 更新前后与回退证据完整；实盘版本与 U 可追溯 |
| 完整能力：可复用研究产品 | 多种可比较学习方式与模型版本，研究/交易训练对象独立管理；必要时研究 Agent 参数 RL | 每项"会学习"声明都有对应更新与独立效用证据 |
