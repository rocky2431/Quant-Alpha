# 09 仿真、影子、执行区与密钥

> **2026-09-18 当前讨论稿｜按 UNIFIED-PLAN v1 细化｜未批准实施。** [索引](README.md) · [总架构](ARCHITECTURE.md) · [MVP](MVP.md) · 上游：[08 学习](08-LEARNING.md)、[03 会计核心](03-ACCOUNTING-CORE-RECONCILIATION.md) · 下游：[10 验证](10-VALIDATION-GATES.md)、[12 生命周期](12-LIFECYCLE-CAPITAL-OPS.md)

## 1. 目的与边界

把策略意图变成可审查的订单、成交、持仓与奖励，并暴露全部市场与执行假设。输入为当时观察、`PolicyVersion`、模型提交的意图、`AccountingSpec`、`EnvState`；输出 `StepTrace`、账户轨迹与训练所需 transition。

三档保真度与一个执行区：

| 档 | 是什么 | 提供什么 | 无法单独证明 |
|---|---|---|---|
| T1 重放 | 真实簿、真实资金费、真实清算规则，对手冻结；建立在 Nautilus backtest 上 | 机械层的精确性 | 市场对新动作的反应、实际下单成功 |
| T2 反应 | 同一起点注入校准过的响应 agent；校准目标必须链上可观测（例如历史上 X bp 簿价偏移的收敛时间分布） | 反身性溢价 Δ(T1,T2)，按下单规模分层 | 校准不过则结果不得用于决策 |
| T3 影子 | 实时 listen-only，不提交订单；Nautilus sandbox | 真实世界机械层地面真值，不需资金 | 真实成交、排队、经济收益 |
| 执行区 | 授权内真实执行，持 trade-only 密钥 | 真实回执、成交、费用、账户 | 长期盈利、其他规模或状态 |

**前置条件**：交易主体的司法辖区与 Hyperliquid 账户资格核实完成前，不建立任何真实账户依赖；这是 [MVP](MVP.md) §6 步骤 0。任何模型只提交意图，执行层做事前限额并签名；这是 [总架构](ARCHITECTURE.md) §5 的全局规则。

## 2. 对象与契约

### 2.1 `StepTrace`

| 字段 | 内容 | 约束 |
|---|---|---|
| `run_id` / `policy_version` / `track_id` / `env_state_id` | 关联键 | 必填 |
| `observed_at` / `decided_at` / `submitted_at` | 观察时刻、推理结束时刻、订单提交时刻 | 不按观察价格立即成交；三者单调不减 |
| `observation_ref` | 观察内容的版本与哈希 | 只含 `usable_at <= observed_at` 的输入 |
| `proposed_intent` | 模型提交的目标仓位或等待 | 原样保留 |
| `risk_checked_intent` | 事前限额处理后的实际动作与改写理由 | 与 `proposed_intent` 并存 |
| `orders` | 客户端 `order_id`、类型、价格、数量、有效期、场所回执 | 幂等 id 由客户端生成；服务端幂等按场所核实 |
| `fills` | 成交、部分成交、拒单、撤单、超时、重复回执标记 | 以场所回执为准 |
| `fees` / `funding` | 交易费、资金费实际结算 | 只在实际可知后入账 |
| `position` / `equity` | 持仓、已实现/未实现盈亏、余额/保证金、估值口径 | 与 `AccountingSpec` 一致 |
| `reward` | 成本后权益变化；风险惩罚单列 | 求和与终局一致 |
| `fidelity` | `T1` / `T2` / `T3` / `LIVE` | 三种模式分报，不混 |
| `episode_state` | 热身、正常、清算、风险终止、数据不可用、截断 | 终止前账户损益不丢 |

### 2.2 执行区权限与密钥

| 区 | 数据权限 | 密钥 | 说明 |
|---|---|---|---|
| 采集区 | 只读市场数据 | 无交易密钥；只读 API key | 录制进程 |
| 研究区 | 只读数据平面 | 无密钥 | 训练、回放、T1/T2 |
| 执行区 | 读写账户状态 | trade-only key 加 IP 白名单；永不开提币 | 策略进程不持私钥，只提交经限额校验的意图 |

三区是权限边界，不预设机器数与进程数；按必要能力选最少组件。密钥规则：每主账户的 Hyperliquid agent 钱包只能下单不能提币，一策略一 agent 以隔离 nonce 与故障归因；主账户用硬件多签；签名进程独立于交易构造 UI，对载荷做独立校验或模拟后再签；权限撤销有清单化 runbook，暴露时先撤权限再转余额。以上来源见 `../2026-09-18-unified-plan/evidence/03-venues-data-2026-09.md` Q6 🟡 与 `evidence/01-institutions-2020-2026.md` §10 ✅。

### 2.3 事前限额（从 `AccountingSpec` 直接算）

| 检查 | 来源 | 处理 |
|---|---|---|
| 订单名义额 ≤ 场所市价单上限 | `AccountingSpec.constraints` | 拒绝并记录 |
| 距 `liq_price` 余量 ≥ 阈值 | `AccountingSpec.liquidation` | 拒绝或缩量 |
| discovery bounds 剩余空间 ≥ 阈值（B 轨） | `AccountingSpec.bounds`、`EnvState.session` | 拒绝新开仓 |
| 单市场、单部署者、总敞口 ≤ 限额 | 风控配置、`EnvState.spec_version` | 拒绝 |
| 数据新鲜度：行情龄、oracle 龄、外部参考源健康 | `EnvState.data_quality` | 陈旧则禁止新增敞口 |
| 环境桶禁入：外部市场盘前、低流动性时段、外部参考源失效 | `EnvState` | 禁止新开仓，允许减仓 |

阈值数值待定，由所有者在实施前确定并预注册。

## 3. 具体过程

1. 从 [02](02-CLEANING-ALIGNMENT-ENVSTATE.md) 与 [07](07-FUSION-SELECTION.md) 取只含当时可用信息的观察，合并自身账户状态与 `env_state_id`。
2. 策略按实际推理与工具耗时得到意图；记录 `observed_at`、`decided_at`。
3. 事前限额把意图转成场所合法订单或拒绝；记录原意图、实际动作与理由。
4. 提交订单，记录 `submitted_at` 与客户端幂等 `order_id`；按到达后的行情与执行模型处理成交、部分成交、拒单、撤单、超时与重复回执。仅有 L2 快照时不伪造队列优先级；成交假设写进 manifest。
5. 更新持仓、盈亏、余额/保证金、费用、资金费；未成交订单不产生虚构仓位。
6. 以一致价格口径估值，计算权益变化与奖励；产生下一观察与 `episode_state`。
7. **独立对账循环**：另一进程按序号与时点从场所 REST 拉取订单、成交、持仓、余额，与本地事件溯源状态对齐；差异记录保留，不做盲目的绝对仓位覆盖；K 次连续偏差触发重拍快照；"订单离簿但无成交摄入"即冻结该标的新开仓；查询未确认订单状态后再决定重试。
8. 三方对账（[03](03-ACCOUNTING-CORE-RECONCILIATION.md)）消费同一事件流，任何不一致进入 `ReconciliationReport`。
9. 保存可从订单、成交、估值重算的完整 `StepTrace`，供 [08](08-LEARNING.md) 训练与 [10](10-VALIDATION-GATES.md) 评价分别使用。
10. 上线前演练：确定性仿真同 seed 两次运行事件序列哈希一致；强制重启后对账无重复订单；kill switch 三级（降规模、只减仓、全平）各演练一次；限速劣化、节点落后、行情缺口三种降级路径各演练一次。

**Nautilus 2.x 的定位**：锁定版本与 commit，作为执行内核、事件溯源与确定性仿真的载体；自有策略与适配器保持独立包并记录 LGPL 边界；不 fork 引擎。Hyperliquid 与 Polymarket 适配器仍在高频修复，上线前用 DST 种子回放与重启对账演练核实（`evidence/04-engineering-platforms.md` Q4/Q5 ✅）。

## 4. 双轨示例

以下数值均为假设。

**轨道 A（BTC 永续）。** `observed_at` 12:00:00，骨架策略于 12:00:00.180 给出"目标小多头 0.02 BTC"；事前限额检查名义额、距清算价余量与数据龄通过；`submitted_at` 12:00:00.210。场所回执：先部分成交 0.012 BTC 于 60,010，随后剩余 0.008 BTC 因超时撤单。`StepTrace` 记录持仓 0.012、开仓费按 taker 0.045% 计 0.324、撤单状态；下一观察必须包含部分仓位。独立对账循环 12:00:05 拉取持仓 0.012 与本地一致；若场所返回 0.020，则记录差异并查询未确认订单，不直接覆盖本地。

**轨道 B（HIP-3 某商品市场）。** `EnvState` 处于 internal 会话，bounds 剩余空间 2.1%，重锚计数 0，外部参考源健康。策略于重开前 3 分钟提交"清仓"意图；事前限额允许减仓。成交后，重开时外部参考源短暂失效（oracle 龄超阈值），`EnvState` 转为禁入桶，任何新开仓被拒绝直到健康恢复；本次 SKHYNIX 式事件的处置记录为"禁入桶生效，无新增敞口"。若持仓未撤出而 bounds 被触发重锚，`StepTrace` 记录重锚事件与 mark 约束路径，供 [10](10-VALIDATION-GATES.md) 归因。

## 5. 失败观测与处置

| 观测 | 候选原因 | 区分方法 | 返回环节 |
|---|---|---|---|
| 回测大量按中间价成交 | 成交模型过于乐观 | 与 T3 影子的真实成交率对照；manifest 标注 | 09 |
| 同一订单重复记账 | 重复回执或重启对账 bug | 幂等 id 去重；重启演练 | 09 |
| 本地"平仓"而场所有持仓 | 重连未重拍快照、回执丢失 | 独立对账循环序号缺口检查 | 09 |
| 资金费方向错误或重复扣 | `AccountingSpec` 口径或市场类型判别错 | 与 [03](03-ACCOUNTING-CORE-RECONCILIATION.md) 独立案例集手算对照 | 03/09 |
| 风险层频繁改写动作 | 策略动作空间与约束不匹配 | 改写率按 `EnvState` 分组 | 08/09 |
| 影子净值被展示成实盘净值 | `fidelity` 标签缺失 | 三种模式分报强制 | 09/12 |
| B 轨在外部参考源失效时开仓 | 禁入桶未生效 | `EnvState.data_quality` 与限额日志 | 02/09 |
| API 返回成功但场所侧订单失败 | 回执语义误读 | 下单后回查状态 | 09 |
| 断流后继续使用旧深度 | 数据龄检查缺失 | 陈旧数据禁止新增敞口 | 02/09 |

## 7. 分阶段能力与证据

| 阶段 | 本环节实质内容 | 验证与推进条件 |
|---|---|---|
| 最小 MVP（对应 10 月 15 日改约交付） | Nautilus 2.x 锁版本接通 HL 适配器；T1 重放对两轨可运行；`StepTrace` 契约与账户/奖励检查通过 [MVP](MVP.md) §5 类例子；独立对账循环与三方对账接入 CI；T3 影子起点；三区权限与密钥 runbook 成文；主体资格核实完成 | 手算与重放一致；等待、部分成交、未成交、期末持仓、越界拒绝有可检查例子；无真实订单 |

| 完整能力：可复用研究产品 | 共用训练/回测/影子/实盘账户语义，持续校准执行，支持多轨与多场所 | 每种工具独立核实规则与适配；更复杂订单按需求增加 |
