## 1. 本套文档要解决什么

把 2026-09-18 统一方案 v1 细化为可逐环节施工与验收的文档集。方案的决策依据、机构与学术证据、与 Codex 的两轮分歧记录都在 `../2026-09-18-unified-plan/`；本套不重复论证，只引用。

所有者对"最小"的定义沿用 9/17 文档："这个最小路径实际上是一个全生命周期的最小验证"，"先跑一个最小示例，暴露我们当前设计上的缺陷"。因此最小化资产数、模块复杂度与实验宽度，保留从数据到下一轮实验的完整生命周期，且按 2026-09-18 裁定以**同一场所双轨**实例化：轨道 A 是 Hyperliquid BTC 普通永续主线，轨道 B 是 HIP-3 会话重开的预算受限支路。

## 3. 文档权威与共同术语

| 标记/术语 | 本套文档的准确含义 |
|---|---|
| **已明确要求** | 自我循环、自主发现、自我验证、自动交易、各环节同步；三层抽象；两速 AI；同一场所双轨 MVP；所有者三项裁定 |
| **设计建议** | 频率、信息源优先级、骨架形态、奖励设计、阈值形态、阶段内容；可在实施讨论中修改 |
| **待定** | 主体资格、B 轨市场清单、数据覆盖、真实延迟、资金与风险门槛、学习配置细节、算力采购 |
| **事实** | 带来源的文档能力或已观察事实，标 ✅/🟡/❌；不把论文结果写成本项目结果 |
| 轨道 A / B / C | A：HL BTC 永续主线；B：HIP-3 会话重开支路，工时 ≤20%；C：Polymarket，以主体资格与数据条件为前提 |
| `EnvState` | 决策时可观测的环境标签：规则版本、市场状态桶、会话状态、数据质量、外部参考源健康 |
| `validity_env` 三态 | 特征在某环境桶的检验状态：有效、反证成立、证据不足；部署可保守拒用后两态 |
| 两速 AI | 慢速推理 Agent 提议不裁决；快速类型化模型做提取与路由并可作受约束选择器候选；所有模型只提交意图，执行层签名 |
| 三类检验 | 历史原样复现（管线一致）、已知信号恢复（学习路径健康）、前向经济检验（有无 edge） |
| 九关 | G0 到 G8，定义在总架构 §6，细则在 10 |
| 独立事件簇 | 数据预算账本的货币；按共同冲击聚簇后计数，不是 K 线数或市场数 |
| 更新规则 U | 预注册的参数更新算法；同一候选内冻结版本与 U，不永久冻结权重 |
| SFT / 数值 RL / LLM Agent RL / 固定 LLM | 分别标注；声称哪种就提交对应真实参数更新与对照 |
| 两层归因 | 上游是来源/实体/事件归属（04）；下游是错误与经济表现诊断（11） |

全局阶段定义由 [ARCHITECTURE.md](ARCHITECTURE.md) 维护；双轨实例参数由 [MVP.md](MVP.md) 维护；局部细节由各环节文档维护；验收规则由 [10](10-VALIDATION-GATES.md) 维护。
