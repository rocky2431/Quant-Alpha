# 07 多源融合、冗余处理与选择

> **2026-09-18 当前讨论稿｜按 UNIFIED-PLAN v1 细化｜未批准实施。** [索引](README.md) · [总架构](ARCHITECTURE.md) · [MVP](MVP.md) · 上游：[05 算子与特征](05-OPERATORS-FEATURES.md)、[06 候选登记](06-CANDIDATE-REGISTRY-FALSIFICATION.md) · 下游：[08 学习](08-LEARNING.md)

## 1. 目的与边界

让异步、不同粒度、不同来源的表示形成有用的共同状态，判断每个来源的条件增量与代价，并把结论写回 `FeatureSpec` 的三态有效域与制约关系。输入为可追溯的 `FeatureFrame`、`FeatureSpec`、`EnvState`、已确认的 `Candidate` 与数据分区；输出 `FusionSpec`、融合状态与选择/消融记录。

**选择器本身是被评价流程的一部分。** 缩放、降维、特征选择、组合权重、门控都不能在最终留出集上决定；它们在开发分区内拟合，在外层时间段上作为整体被评价。LLM 选择"下一项研究实验"与模型选择"此刻的资金权重"是两件事，前者归 [11](11-RESEARCH-FEEDBACK-AGENT-LOOP.md)，后者归本环节与 [08](08-LEARNING.md)、[10](10-VALIDATION-GATES.md)。

## 2. 对象与契约

`FusionSpec` 字段级定义：

| 字段 | 内容与限制 |
|---|---|
| `fusion_id`、`track_id`、`candidate_id` | 标识与归属 |
| `modality_groups[]` | 市场/微观、语义、会话与机制、质量与数据龄、账户；每组列出 `feature_version` |
| `route` | 结构化融合 / 模态编码后融合 / 专家输出后融合，见 §3 |
| `selection_rule` | 特征选择方法、拟合范围 `fit_scope`、冻结规则 |
| `combination_rule` | 组合方式与权重；门控若存在，写明其输入只含当时已揭晓的结果 |
| `missing_policy` | 缺失与数据龄如何作为状态进入模型，不填零、不前向填充过期值 |
| `training_scope` | 训练分区与更新节奏 |
| `ablations[]` | 每次消融的对照条件、分区、结果、`EvaluationBundle` 引用 |
| `redundancy_groups[]`、`shared_exposure_groups[]`、`conditional_complements[]` | 由消融得出，写回对应 `FeatureSpec` |
| `budget_used` | 消耗的候选数与试验数，计入 `Candidate.trials_used` |
| `version`、`frozen_at` | 冻结版本 |

**三种融合路线**：

| 路线 | 过程与优势 | 主要限制与何时增加 |
|---|---|---|
| 结构化融合 | 时间对齐后的数值、事件字段、缺失与数据龄状态交给线性加收缩、树模型或小型网络 | MVP 起点，易归因；若丢失序列或语义结构，再检验独立编码器 |
| 模态编码后融合 | 市场序列与文本/事件各自编码，用时间或跨模态结构连接 | 需足够样本与真实时间掩码；只有简单表示确实丢失有效信息时增加 |
| 专家输出后融合 | 分别预测收益、风险、成交等，组合预测或专家决策 | 易独立比较，需校准与误差互补；门控本身可能过拟合 |

三种路线在共用接口内比较；不预先认定某种骨干适合所有融合。

## 3. 具体过程

1. 按来源与用途分组：市场、语义、会话与机制、质量与数据龄、账户；保留单位与更新频率。
2. 以 [02](02-CLEANING-ALIGNMENT-ENVSTATE.md) 的可用时点连接数据；缺失与过期作为状态进入模型；陈旧事件不当新事件多次计数。
3. 先固定一个简单融合基线（结构化融合加线性或树模型）；任何可学习变换只在 `fit_scope` 内拟合。
4. 检查训练期相关性、重复实现、分布与资源消耗，形成候选冗余组。
5. 用按时间与事件簇分组的消融检验条件增量：对每个来源、每个 `EnvState` 桶，比较"有该来源"与"无该来源"的同模型同预算结果。高相关可以同时携带时效或质量差异；低单独 IC 可以有风险过滤、成交或交互价值。
6. 识别共同暴露：把组合的持仓按风险因子分解，找出多个特征重复押注的方向；组合时按暴露计权。
7. 识别条件互补：某特征只在另一特征定义的桶里有增量时，记录 `conditional_complements`，并把该桶写入前者 `validity_env`。
8. 对专家组合，先比较单独专家与固定等权组合，再讨论动态门控；门控训练只使用当时已揭晓的专家结果，标签未到期不更新。
9. 把消融结论写回每个 `FeatureSpec` 的 `validity_env` 三态与制约关系字段；保留删除原因与预算；交 [10](10-VALIDATION-GATES.md) 在外层时间段评价整个选择流程。

## 4. 双轨示例

**轨道 A（假设）。** MVP 把订单流、资金费状态、价差、深度失衡、波动、语义变化字段、事件龄与数据龄、持仓一起输入结构化融合基线。没有新宏观事件时，状态是"无新事件加旧事件龄"，不用空值替代语义，也不用旧值装作新发布。消融结果假设为：语义字段在"高波动、新事件"桶内成本后有增量，在其他桶无增量；`event_age` 与 `spread` 存在条件互补。写回：语义字段 `validity_env` 在前者为有效、其余桶为证据不足；`conditional_complements` 记录该关系。若加入语义后换手上升、净收益下降，至少比较三项：移除语义、保留语义但加数据龄与流动性交互、同成本规则下的固定组合，以区分"信息无效"、"表达错误"、"过度响应"。

**轨道 B（假设）。** 输入会话状态、距重开时长、bounds 剩余空间、重锚定计数、冻结价与 oracle 差、跳幅分层、内部簿深度与价差、账户。消融假设为：跳幅分层与 bounds 剩余空间高度相关但时效不同（后者随会话内价格变化），归入同一冗余组但保留两者，组内只让一个进入骨架的入场判据；冻结价与 oracle 差在"外部参考源不健康"桶内无定义，该桶标为无定义而非反证成立。若某个来源缺失时策略失控，用来源屏蔽与延迟情景对照保守动作。

## 5. 失败观测与处置

| 观测 | 候选原因 | 区分方法 | 返回环节 |
|---|---|---|---|
| 单模块有效，组合反而变差 | 尺度或校准不同；同一风险重复下注 | 固定组合与校准对照；持仓共同暴露分析 | 07 步骤 6 |
| 只在训练上选择效果好 | 选择偏差或状态拟合 | 外层时间验证；记录整个搜索预算 | 10 |
| 某来源缺失时失控 | 缺失语义未进入训练 | 来源屏蔽与延迟情景，对比保守动作 | 07 步骤 2、05 |
| 注意力图看似合理但无增量 | 可视化不等于经济机制 | 移除或替换信息后的独立表现 | 07 步骤 5 |
| 组合切换频繁 | 标签滞后、近期噪声、不含换手成本 | 固定权重与不同预定更新节奏对照 | 07 步骤 8 |
| 门控使用了未揭晓结果 | 泄漏 | 检查门控输入的 `available_at` | 07 步骤 8、02 |
| 消融结论未写回 `FeatureSpec` | 流程遗漏 | 校验每个 `ablations[]` 有对应写回 | 07 步骤 9 |
| 桶内样本太少，三态判定不稳 | 桶划分过细 | 合并桶或标证据不足 | 02/05 |

## 7. 分阶段能力与证据

| 阶段 | 本环节实质内容 | 验证与推进条件 |
|---|---|---|
| 最小 MVP（对应 10 月 15 日改约交付） | 两轨各一个结构化融合基线；明确缺失与数据龄状态；一组"市场独立"与"市场加语义"（A）、"有会话状态"与"无会话状态"（B）的消融；消融结论写回 `FeatureSpec` 三态有效域；选择过程留痕 | 同模型同预算下能回答新信息是否有条件价值；不只展示组合回测峰值；每个来源的写回可查询 |
| 第二步：针对失败补强 | 针对丢失的序列或语义测试编码器；针对校准或重复暴露补约束；针对无用字段删减 | 新结构相对简单融合改善预定问题，并在后续开发窗口成立 |
| 第三步：跨状态与运行验证 | 检验专家互补性、延迟与缺失、漂移与动态门控；门控接受外层评估；跨更多独立事件簇复核三态有效域 | 成本后改善与切换稳定性得到独立证据；单一状态的胜利不够 |
| 完整能力：可复用研究产品 | 可配置的信息组合与用途对照，复用编码器与专家，解释每个新增来源的边际作用 | 新任务沿用同一评价规范；新增模态或专家依据需求与证据 |
