## 1. 目的与边界

这是"归因"的第二层：把可观察的失败转成可证伪原因与下一项实验，使研究根据结果改变。它诊断模型、交易与研究流程的错误与经济表现，区别于 [04](04-EXTRACTION-SEMANTICS.md) 的来源与事件归属。一次合理解释不是因果证明；一项未测试的建议不构成完整改进循环。

本环节也是 Agent 研究回路的落点：慢速推理 Agent 在这里提议假设、特征代码、算子、下一项实验与研究记忆的更新。它更新的是研究方向与代码，不是自身权重；研究 Agent 的参数 RL 留待累积足够可评价的研究轨迹之后。

输入：开发分区的 `EvaluationBundle`、`StepTrace`、`ReconciliationReport` 的漂移信号、数据/训练版本与预算。输出：`ResearchDecision`、新的或修订的 `Candidate`，以及后续实验结果与保留/回退/淘汰决定。若使用最终留出结果开启新轮次，该结果重新标为开发证据。

## 2. 对象与契约

**`ResearchDecision`**

| 字段 | 内容 |
|---|---|
| `decision_id` / `research_cycle_id` / `track_id` | 标识与轨道 |
| `observation` | 观测与证据引用（`EvaluationBundle` 字段、`StepTrace` 区间、`ReconciliationReport` 差异） |
| `candidate_causes` | 最少数量、能区分的候选原因，各自可反驳 |
| `discriminating_experiment` | 只改变什么、保持什么、用哪段数据、预计改变的中间指标与最终指标、什么结果会反驳 |
| `budget` | 算力、API token、人工时、允许的变体数 |
| `trial_count` | 本决定累计的独立试验数与变体数，回写 10 的 `trial_ledger` |
| `actual_result` | 实施后的实际结果与是否符合预期 |
| `verdict` | 保留 / 修改 / 回退 / 淘汰，及尚未区分的原因 |
| `provenance` | 提议者（人 / Agent 模型与版本）、所用外部资料与其可得时间、生成代码经过的白名单工具 |
| `versions` | 代码、模型、数据、`spec_version`、`feature_version` |

**研究记忆**：结构化的实验记录与失败清单，按 `research_cycle_id` 组织；不建复杂记忆平台。记忆中不得混入本轮未开放的最终留出内容；事件之后形成的论文或外部知识只能用于后续真实可得的研究轮。

**研究预算单位与停止条件**：预算按研究轮登记，单位为试验数、变体数、GPU 小时、token、人工时；每轮预注册停止日期。停止的合法理由包括假设被否定、证据不足、预算耗尽，不需要通过扩展架构来避免负面结论。

## 3. 具体过程

1. **核对计算**：确认 `EvaluationBundle` 的比较使用同信息、同风险、同执行条件；对账漂移先看 03，账本错误先修复再谈策略。
2. **分离观测与解释**：列出最少数量的候选原因，优先检查直接证据（时间戳、版本、费用、成交）。
3. **提出区分实验**：为候选原因写干预或消融，写出预计变化的中间量与最终量，以及反驳条件。
4. **预算内选择下一项实验**：明确只改一处、保持什么、用哪段数据；`trial_count` 累加。
5. **实施并运行**：在获准实施阶段真正实现变化、运行实验、保存结果。只生成计划不算完成循环。
6. **判定**：保留、回退、重新定位或有证据地放弃；记录尚未区分的原因。
7. **冻结与交付**：整个流程冻结后交 10 做独立评价；证据不足可以停止。

**污染防线**（每条都是机制，不是约定）：

| 防线 | 实现 |
|---|---|
| 评估器在 Agent 权限之外 | 九关代码、阈值文件、分区清单对 Agent 只读；修改走人审 PR 与哈希更新 |
| 只读开发结果 | Agent 的数据访问凭证只覆盖开发分区与已开放的 `EvaluationBundle` |
| 试验计数必填 | `ResearchDecision` 无 `trial_count` 程序拒收；计数回写 10 |
| 多模型并行采样 | 同一诊断任务至少两个不同家族模型独立提议，记录提案相关性；同质化高时扩大采样而非采信 |
| 外部文本不可信 | 场所公告、论坛、论文可促成提议，不能授权变更；变更只由对账 CI 或人审授权 |
| 白名单数据访问 | Agent 生成的特征代码只能通过 05 的算子接口读数据，接口强制 `available_ts` 过滤 |
| 记忆隔离 | 研究记忆按可得时间标注；最终留出结果只在开启后写入 |

## 4. 双轨示例

**以下为预期实施流程，非已发生结果。**

**A 轨。** 观测：`A-v0` 在开发事件簇上宏观事件后频繁换向，毛收益正、成本后净增量负。两个解释：H1 同一事件被重复计为新信息；H2 信息有用但动作对很小优势反复响应。先做区分：检查 `EventEvidence` 的 `event_id` 与更新时间、动作轨迹；若无重复更新，不能沿用 H1。V1：观察、预算、环境不变，加入预定义的换仓滞后或成本门槛；预期无效换手下降、费用减少、有效事件响应不整体消失。后续在未用于选择该修改的开发后段比较 V0 与 V1，并与固定研究计划同预算比较。决定：符合预期且净改善则保留进冻结；只降交易但失去有效信号则不接受原解释；依旧无增量则淘汰。

**B 轨。** 观测：`B-v0` 亏损集中在跳幅小于 25bp 的重开。两个解释：H1 小跳幅事件本来就是在给隔夜风险定价，无残差；H2 入场过早，被休市内噪声打穿。区分：按 `EnvState` 的 bounds 剩余与距重开时长分组看盈亏分布；若小跳幅组在任何入场时点都为负，支持 H1。V1：按跳幅分层的入场门槛，同时保留大跳幅组不变。若 V1 只是让 B 不再交易小跳幅事件而大跳幅组也无正期望，则零假设 (1) 未被证伪，B 降级。

## 5. 失败观测与处置

| 观测 | 候选原因 | 区分方法 | 返回环节 |
|---|---|---|---|
| 信息在回测中比实时早出现 | 可用时间/修订/处理延迟错误 | 真实接收与假设延迟对照；重做时点视图 | 01 / 02 |
| 三方对账红灯 | spec 错、场所改参、适配器不符、口径差 | 三方差异定位表；已知变更注入对照 | 03 |
| 条件声明被当成已生效事实 | 提取或事件归属错误 | 原文复核，纠正字段后重放同策略 | 04 |
| 事件加入后只产生冗余信号 | 表示未含变化、时效或条件状态 | 加入事件龄/交互或撤掉重复字段 | 05 / 07 |
| 候选登记后证伪脚本无法运行 | 脚本依赖未冻结数据或阈值哈希不匹配 | 重新登记，缺项拒收 | 06 |
| 训练强、后续失效 | 选择偏差、过拟合、状态变化、输入失真 | 时间/事件簇隔离；同输入不同约束；外层评价 | 07 / 08 / 10 |
| 毛增益被成本吞噬 | 行动过频、机会太小、执行假设不合理 | 固定信息，比较预定动作节奏与真实成本敏感性 | 08 / 09，必要时否定机会 |
| 虚假成交、账本不平 | 环境或账户错误 | 用原始订单/成交手算与重放 | 09 |
| 同信息下完整 RL 或 LLM Agent 无增量 | 任务无需该复杂度，或训练/奖励无效 | 基线、奖励诊断、受限候选对照 | 08 / 10 |
| Agent 提案高度同质 | 单模型采样 | 多模型并行，记录相关性 | 本环节 |
| 数据正确、对照充分仍无信号 | 机制假设不成立或效应不足 | 依预注册否定条件淘汰 | 06 新卡片或停止 |

更大网络、新数据、生成模型、RL 都只是可能手段；先说明哪个观测需要它。

## 6. 两速 AI 在本环节的权限

| 环节动作 | 慢速推理 Agent | 快速类型化模型 | 数值/确定性程序 | 裁决者 |
|---|---|---|---|---|
| 核对结果计算 | 可复核并指出差异 | — | 重算 | 重算结果 |
| 提出候选原因 | 提议，至少两个模型独立 | — | — | 区分实验 |
| 设计区分实验 | 提议，含可反驳预期 | — | 检查数据依赖与分区 | 分区权限加预注册 |
| 编写实验代码 | 提议代码，经白名单算子接口 | — | CI 运行 | 已知信号恢复与 lint |
| 选择下一项实验 | 在预算内提议 | 可对候选原因做初筛路由 | 扣减预算 | 预算账本 |
| 判定保留/淘汰 | 提议 | — | — | 预注册否定条件与实际结果 |
| 更新研究记忆 | 写入结构化记录 | — | 按可得时间标注 | 记忆隔离规则 |
| 修改评估器或阈值 | 不可 | 不可 | — | 人审 PR 加哈希更新 |

## 7. 分阶段能力与证据

| 阶段 | 本环节实质内容 | 验证与推进条件 |
|---|---|---|
| 最小 MVP（对应 10 月 15 日改约交付） | 两轨各完成一次"结果→诊断→区分实验设计→预算登记"，并对 G5 定位的泄漏或 G1 失败完成实际修复与重跑；`ResearchDecision` 契约与污染防线机制就位；固定 LLM 加研究记忆参与 | 修改可追溯到证据并核对其预测；不能只有总结与待办；与固定研究清单的比较可以标"未运行" |
| 第二步：针对失败补强 | 针对已见重复失败改善诊断字段、实验选择与证据检索；减少无效重复实验 | 等预算下更有信息量的实验或更少重复；无证据不新增 Agent 层级 |
| 第三步：跨状态与运行验证 | 研究结论跨事件簇与 `EnvState` 复核；用真实前向偏差更新候选；E4 在外层分区完成 | 改进不依赖反复查看同一最终集；更新与停止都有合理证据 |
| 完整能力：可复用研究产品 | 可审查的假设/失败/实验资产跨轨复用；有需要时训练研究选择策略 | 研究效率与经济增量分别与固定流程比较；自动化程度不是唯一目标 |

## 8. 依赖与待定

依赖 10 提供开发分区的 `EvaluationBundle` 与 `trial_ledger`；03 提供漂移信号；06 接收新卡片并校验八项必填；05 提供白名单算子接口；12 接收保留/淘汰决定以驱动 `LifecycleState`。待定：每轮研究预算的具体数字与停止日期、多模型采样的模型清单与相关性阈值、人工参与边界、研究记忆的存储位置与访问控制实现。停止可以因为假设被否定或证据不足，不需要通过扩展架构来避免负面结论。
