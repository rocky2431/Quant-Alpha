# 比特币金融机器学习全生命周期：讨论文档索引

> **2026-09-17 语音讨论稿｜用于详细讨论和独立比较｜未批准实施。** 当前授权是编写本套中文文档；没有授权运行 MVP、安装、购买数据、训练、部署或交易。

## 1. 本套文档要解决什么

同时提供一张完整框架图和一条可逐步执行的比特币最小验证路径。用户已有 Qlib 因子研究与树模型预测经验，希望突破在相似 OHLCV 输入上反复搜索冗余表达式的固定流程，引入及时的异构信息、有效表示和组合，并贯通研究、真实参数学习、交易决策、评价和反馈。

用户对“最小”的关键定义是：

> “这个最小路径实际上是一个全生命周期……的最小验证。”
>
> “先用比特币去跑一个最小示例……能够……暴露出来我们在当前的设计上的一些缺陷。”

因此，最小化资产数、模块复杂度和实验宽度，同时保留从数据到下一轮实验的完整生命周期。文档现在就描述各阶段的完整前景；实施从讨论后的 BTC 最小骨架开始。

## 3. 文档权威与共同术语

| 标记/术语 | 本套文档的准确含义 |
|---|---|
| **已明确要求** | 全局框架和 BTC 全生命周期最小验证；宏观/语义与微观结构均须进入最小路径；详细中文文档；先讨论再实施 |
| **设计建议** | 骨干、交易品种形态、频率、数据来源优先级、奖励设计及阶段内容；可在讨论中修改 |
| **待定** | 交易场所、合约、数据覆盖、时间范围、真实延迟、风险和经济门槛、学习配置及资源 |
| **事实** | 带来源的文档能力或已观察事实；不把论文结果写成本项目结果 |
| 因子/表示 | 信息结构或变换结果；不是独立学习范式，低单因子 IC 不等于没有条件价值 |
| SFT | 使用示范/监督数据实际更新模型参数；人工看报告、改提示词不自动构成 SFT |
| 数值策略 RL | 根据行动、状态和奖励更新数值策略参数 |
| LLM Agent RL | 更新承担工具调用/交易决策的语言模型参数；需对应轨迹和同模型对照 |
| 研究反馈 | 证据改变下一轮假设、数据、表示或实验选择；初期可以使用固定 LLM 和研究记忆 |
| 两种归因 | 上游是来源/实体/事件归属；下游是错误与经济表现的诊断。统计关联不自动等于经济因果 |
| 独立评价 | 不向本轮搜索、特征选择、研究记忆或训练提供反馈的未来时间/事件组 |
