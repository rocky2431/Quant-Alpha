# 09 失败归因、研究反馈与有目标的补强

> **2026-09-17 当前讨论稿｜未批准执行后续实验。** [索引](README.md) · 上游：[08 验证](08-VALIDATION.md) · 返回：[总架构](ARCHITECTURE.md)

## 1. 目的与“归因”的第二层含义

把可观察的失败转成可证伪原因和下一项实验，使研究根据结果改变。这里是模型、交易和研究流程的诊断，区别于 03 的来源/事件归属。一次合理解释不是因果证明，一项未测试的建议也不构成完整改进循环。

输入为开发期 `EvaluationBundle`、完整轨迹、数据/训练版本及预算；输出 `ResearchDecision`、新/修订 `HypothesisCard`，以及后续实验结果和保留/回退/淘汰决定。若使用最终评价结果开启新轮次，该结果需重新标为开发证据。

## 2. Agent 的具体工作

1. 核对结果计算是否正确，以及比较是否使用同样信息、风险和执行条件。
2. 分离观测和解释，列出最少数量、能区分的候选原因；优先检查直接证据。
3. 为候选原因提出干预/消融，写出预计改变的中间指标和最终指标，以及什么结果会反驳它。
4. 在预算内选择下一项实验，明确只改变什么、保持什么、用哪段数据。
5. 在后续获准实施阶段真正实现变化、运行实验，保存结果。仅生成修改计划不算完成循环。
6. 根据实际结果保留、回退、重新定位，或有证据地放弃原假设；记录理由和尚未区分的原因。
7. 对整个研究流程冻结后进入独立评价。若证据不足可以停止，不以“必须找到盈利组合”为继续搜索条件。

MVP 可用固定 LLM、结构化实验结果和研究记忆执行上述步骤，不要求训练研究 Agent 参数。若后续研究参数 RL，要把实验选择/预算分配作为动作、独立研究结果作为目标，并重新验证其增量，不能由记忆变化直接宣称完成。

## 3. 失败路由：什么证据指向什么补强

| 观测 | 候选原因 | 区分实验/修复 | 应返回环节 |
|---|---|---|---|
| 信息在历史回测中比实时早出现 | 可用时间/修订/处理延迟错误 | 真实接收与假设延迟对照；重做时点视图 | 01/02 |
| 将条件声明当已生效事实 | 提取或实体/事件归属错误 | 原文复核，纠正字段后重放同策略 | 03 |
| 事件加入后只产生冗余信号 | 表示未包含变化、时效或条件状态 | 有理由地加入事件龄/交互或撤掉重复字段 | 04/05 |
| 训练很强，后续失效 | 选择偏差、过拟合、状态变化、训练输入失真 | 时间/事件隔离、同输入不同学习/约束、外层流程评价 | 05/06/08 |
| 毛增益全部被成本吞噬 | 行动过频、机会太小或执行假设不合理 | 固定信息，比较预定动作节奏/持仓规则与真实成本敏感性 | 06/07，必要时否定机会 |
| 虚假成交、账本不平 | 环境/账户错误 | 用原始订单/成交手算与重放，修复后重跑受影响结果 | 07 |
| 相同信息下 RL 没有增量 | 任务无需该决策复杂度，或训练/奖励无效 | 基线、奖励诊断及受限候选对照；无证据则保留基线 | 06/08 |
| 数据正确、对照充分仍无新增信号 | 机制假设不成立或效应不足 | 依据预注册否定条件淘汰；若有新机制再开新卡片 | 研究问题 |

更大网络、新数据、GAN、RL 都只是可能手段；先说明哪个观测需要它。金融市场的事后叙事不应代替区分实验。

## 4. BTC 完成一次循环的示例

以下是**预期实施流程，非已发生结果**：

| 步骤 | 具体内容 |
|---|---|
| 观测 | 假设版本 V0 的事件＋微观 RL 在若干开发事件中频繁换向，毛收益为正而净增量为负 |
| 两个解释 | H1：同一事件被当成多条新信息；H2：信息有用，但动作对很小优势反复响应 |
| 先做区分 | 检查事件 ID、更新时间和动作轨迹；若没有重复更新，不能沿用 H1 的故事 |
| V1 实验 | 在观察和训练预算不变条件下，加入预定的换仓滞后/成本门槛，或修复已发现重复事件；一次只采用有证据的变化 |
| 预期 | 无效换手和费用下降；有效事件响应不应整体消失；明确可能的毛收益下降代价 |
| 后续检查 | 在未用于选择该修改的开发后段/新事件组比较 V0 与 V1，并与固定研究计划同预算比较 |
| 决定 | 效果符合且净经济改善：保留进入冻结；只降低交易但失去有效信号：不接受原解释；依旧无增量：淘汰或重提假设 |

这才把“反馈”连接到实际研究选择和检验。随后仍需要 08 的独立评价；此表不是声称减少换手一定盈利。

## 5. 必须保留的研究记录

每次决定至少包含观察及证据引用、候选原因、可反驳预期、改变项/保持项、数据用途、预算、代码/模型/数据版本、实际结果和判断。不要求搭建复杂记忆平台；用现有实验记录即可，但失败记录不能丢弃。

记录中不得混入本轮未开放的最终留出内容。论文/外部知识若是在事件之后形成，只能用于后续真实可得的研究轮，不能回写成历史 Agent 当时知道的内容。

## 6. 分阶段能力与证据

| 阶段 | 本环节实质内容 | 验证与推进条件 |
|---|---|---|
| 最小 MVP | 一次完整“结果→诊断→后续实验→实际检查→决定”；固定 LLM/记忆可参与；失败可导致放弃 | 能把修改追溯到证据并核对其预测，不能只有总结和待办；与固定研究比较的结论诚实报告 |
| 第二步：针对失败补强 | 针对已见重复失败改善诊断字段、实验选择和证据检索，减少无效重复实验 | 等预算下可观察到更有信息量的实验或更少重复；无证据不新增 Agent 层级 |
| 第三步：跨状态与运行验证 | 研究结论跨事件/状态复核，使用真实前向偏差更新候选；检验适应速度和误改频率 | 改进不依赖反复查看同一最终集，更新和停止都有合理证据 |
| 完整能力：可复用研究产品 | 可审查的假设/失败/实验资产，跨任务复用已验证认识；有需要时训练研究选择策略 | 研究效率及经济增量分别与固定流程比较；自动化程度不是唯一目标 |

## 7. 相邻依赖与待定

01–07 提供可定位的中间证据，08 决定哪些结果可进入研究反馈。待定为实验预算、停止条件、研究流程控制组和人工参与边界；停止可以因为假设被否定或证据不足，不需要通过不断扩展架构来避免负面结论。
