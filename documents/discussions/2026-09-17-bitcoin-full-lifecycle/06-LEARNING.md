# 06 预测、策略与 Agent 学习

> **2026-09-17 当前讨论稿｜未批准训练、模型安装或算力采购。** [索引](README.md) · 上游：[05 融合](05-FUSION-SELECTION.md) · 交互：[07 环境](07-SIMULATION-EXECUTION.md)、[08 验证](08-VALIDATION.md)

## 1. 目的与学习对象

从信息表示产生预测和完整交易决策，并能够证明具体学习改变了什么。输入为融合状态、训练分区、目标、环境/动作/奖励和初始化模型；输出 `TrainingRun`、`PolicyVersion`、预测、轨迹及可核对的训练产物。

| 路径 | 实际更新什么 | 可称为完成训练的必要证据 |
|---|---|---|
| 普通监督/自监督 | 预测器或编码器权重 | 数据/目标、初始化与最终模型、训练记录及样本外输出 |
| SFT | 用示范或标注更新语言/工具策略参数 | 示例来源、训练分区、权重/适配器、留出任务表现；人工监督本身不算 |
| 数值策略 RL | 根据市场/账户轨迹更新数值策略参数 | 真实 rollout、状态动作奖励、优化记录、权重变化及策略对照 |
| LLM Agent RL | 更新执行工具调用或交易决策的 LLM 参数 | 与实际工具轨迹对应的训练输入/奖励、可核对参数更新、同模型 SFT-only 对照 |
| 固定 LLM＋研究记忆 | 提示、检索内容、研究记录 | 属于研究流程更新；不声称已训练 Agent 权重 |

LSTM/Transformer 是骨干，GAN 是训练/生成机制，监督学习和 RL 是学习方式。因子仍是信息接口，RL 可以学习进入、方向、规模、等待、调整和退出；场所不支持的动作不能进入策略。

## 2. MVP 的学习配置建议与边界

共享 BTC 全生命周期支持两种候选配置：

- **配置 N：数值策略路径。** 使用已有树模型或小型序列模型做同信息预测基线，小型数值策略 RL 学习完整目标持仓动作。作为便于验证账户/奖励的首个配置建议，不代表已选定算法；PPO 是候选之一。
- **配置 L：语言工具策略路径。** 同一基础 LLM、相同工具和信息，比较 SFT-only 与 SFT＋RL；RL 必须更新该 Agent 的参数。更高的推理延迟要进入可成交时点。若本次验收包含原先的真实 LLM Agent RL 要求，就必须完成本配置对应证据，配置 N 不能代替。

二者使用同一研究和账户框架，避免把研究自动化与交易策略拆成二选一。**待定：**第一轮优先实例化哪一配置、是否本期两者都验收、资源预算。文档先完整规定两者，未通过默认配置撤销历史交付要求。具体比较见 [BTC-MVP.md](BTC-MVP.md)。

## 3. 训练过程

1. 固定任务、观察字段、动作能力、账户/奖励口径及分区用途；先确认奖励能由 07 重算。
2. 建立强而简单的同信息基线。预测可用未来实际收益作监督标签，但政策观察不包含未到期标签。
3. 若策略依赖预测器输出，建议在训练段内产生滚动样本外预测供策略训练，降低“训练时完美预测、部署时噪声预测”的差异。
4. SFT 路径准备基于当时观察的示范/工具轨迹，并检查动作和来源。用未来结果筛选训练样本时仍限定训练分区，不能把未来信息写回示范观察。
5. RL 在训练环境中采样连续轨迹，实际优化对应策略参数。记录等待、未成交、持仓风险、资金费、非法动作及实际执行动作。
6. 在开发分区选择候选；比较相同信息、风险、成本和预算的控制组。训练曲线不能替代经济评价。
7. 冻结模型、特征/融合版本、奖励、工具、提取器、动作转换及环境配置，交 08 独立评价。

## 4. LLM Agent RL 的具体证明要求

配置 L 需要记录观察到的上下文、真实工具调用与回执、动作/等待、对应账户后果和训练所用的实际模型轨迹。训练器必须支持所定义的多步反馈；不能把单步涨跌分类或格式分数包装成完整账户 RL。

同模型比较至少保持基础 checkpoint、工具权限、观察信息、预算与执行假设一致；可明确报告 SFT 与 RL 额外训练成本。参数差异只证明发生更新，还要检查更新后行为与独立指标。研究 Agent 自身的参数 RL 另行作为后续候选，不能由交易 Agent 的 RL 或研究记忆更新推定已经完成。

## 5. BTC 示例与失败

观察包括宏观事件字段、事件/行情龄、价差、深度/成交、风险状态和自身持仓。策略可以等待、建立允许方向的仓位、增减仓或退出；它不需要重新发现账户恒等式。奖励使用 07 的成本后权益变化，额外风险惩罚单独记录，最终比较仍展示原始经济结果。

| 观测 | 需要检查 |
|---|---|
| 训练奖励上升，未来净收益下降 | 过拟合、模拟器漏洞、选择偏差、预测输入分布差异 |
| 总是空仓 | 可能是合理放弃，也可能是奖励/探索问题；同信息机会与风险对照区分 |
| 大量动作被风险层改写 | 动作空间/约束学习问题；不能只展示改写后的漂亮结果 |
| LLM 解释正确但动作过晚 | 推理/工具延迟与机会生命周期不匹配 |
| 历史成交数据无法覆盖新动作 | 离线 RL 的分布外行动/反事实识别问题，不能靠历史 K 线自动解决 |

离线数据的动作覆盖与价值估计边界参见 [Offline Reinforcement Learning](https://arxiv.org/abs/2005.01643)。学习得到的世界模型同样需要独立检验，不能用自身生成数据证明自身有效。

## 6. 分阶段能力与证据

| 阶段 | 本环节实质内容 | 验证与推进条件 |
|---|---|---|
| 最小 MVP | 明确的监督基线与真实 RL 候选；配置 L 若纳入验收则有实际 SFT/RL 和同模型对照；学习产物接入完整账户轨迹 | 更新对象与产物一致，可复现策略输出；经济增量可为负，不能以此伪造训练成功或替代业务验收 |
| 第二步：针对失败补强 | 针对具体误差更改观察、监督目标、约束、训练或骨干；需要语义能力时补 SFT；比较固定输入下的改进 | 区分实验支持原因，修改后的预测效果在后续窗口被验证；不默认扩大网络 |
| 第三步：跨状态与运行验证 | 检验标签延迟、漂移、预定再训练、实时推理及跨状态稳定性；对动态更新策略整体评价 | 更新前后及失败回退证据完整，实盘版本/更新规则可追溯 |
| 完整能力：可复用研究产品 | 多种可比较学习方式和模型版本，研究/交易训练对象独立管理；必要时研究 Agent 参数 RL | 每项“会学习”声明都有对应更新和独立效用证据；更大模型/世界模型按需要论证 |
