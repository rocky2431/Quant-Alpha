# 01 数据来源与接入

> **2026-09-17 当前讨论稿｜未批准实施或数据采购。** [索引](README.md) · [总架构](ARCHITECTURE.md) · 下一环节：[清洗与对齐](02-CLEANING-ALIGNMENT.md)

## 1. 目的与边界

把研究问题转换为具体、可取得、可追溯的数据需求。接入完成的标准包含覆盖和使用条件，不是接口返回一次成功。用户列举的社交、宏观、新闻财报、交易所、链上和预测市场构成候选信息目录，不要求最小实验一次接齐。

输入为 `HypothesisCard`、交易工具候选、时间/延迟需求和数据预算约束。输出为来源清单、覆盖报告及 `RawRecord`，交给 02 处理；原始内容同时供 03 回查证据。

## 2. 来源目录与用途

| 数据类型 | 候选来源与用途 | 取得前必须区分 |
|---|---|---|
| BTC 行情与微观结构 | 所选场所的逐笔成交、买卖报价、深度、订单事件；形成流动性与交易状态 | K 线、L2 快照、L3/订单事件不是等价历史；快照间的排队和成交不能凭空恢复 |
| 宏观官方事件 | FOMC 声明/日历、统计发布及其历史版本 | 声明、记者会、纪要是不同发布时间的事件；修订值不回填过去 |
| 新闻与公开人物言论 | 官方渠道、新闻供应商、X 上政策相关公开发言；提取主张与变化 | 原帖、转述、修正、引用不同；当前互动量不等于发布当时互动量 |
| 公司披露 | SEC 申报/XBRL 等，作为与 BTC 相关公司的公开信息候选 | 报告期、公开申报时刻、修订版本不同；不能把全部财报默认为 BTC 有效信息 |
| 链与市场上下文 | Hyperliquid 交易/资金费/链事件、其他公开链上聚合数据 | 原始地址不自动具有可靠身份标签；数据粒度、最终性和到达时间需注明 |
| 预测市场上下文 | Polymarket 事件、YES/NO token、成交/盘口 | 合约定义和结算条件决定可比性；价格包含流动性和摩擦，不是无条件真实概率 |
| 自身账户 | 持仓、可用资金、订单、成交、费用和风险事件 | 真实账户、模拟账户、影子账本分开，不能互相补造成交 |

当前官方说明提供以下能力边界：Hyperliquid 有 L2/资产上下文及节点相关历史路径，但提醒可能缺段、更新不及时且传输由请求方付费；本轮未下载。ALFRED 可以按历史实时期取得当时已知版本，默认 FRED 侧重今日版本。[Hyperliquid 历史数据](https://hyperliquid.gitbook.io/hyperliquid-docs/historical-data)、[FRED 与 ALFRED](https://fred.stlouisfed.org/docs/api/fred/fred_vs_alfred.html)。

其他同日讨论已核对的入口：[SEC API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)、[X 搜索](https://docs.x.com/x-api/posts/search/introduction)、[Polymarket 市场发现](https://docs.polymarket.com/market-data/discover-markets)、[盘口](https://docs.polymarket.com/market-data/prices-order-books)、[实时数据](https://docs.polymarket.com/market-data/realtime-data)。能力说明不证明已取得完整历史。语音中的“Hyperliquid 盘前”含义仍未定，不能据此选定盘口或盘前产品。

## 3. 具体接入过程

1. 从假设列出必要字段、最低粒度、观察期及允许延迟，并说明每个字段的预期贡献。
2. 检查历史和实时路径能否提供同一种字段/语义，记录取数权限、成本、限制和缺段。
3. 在后续获准实施时先取有代表性的事件日与普通日样本，核对内容和时间；样本检查不代替全期覆盖检查。
4. 原始内容保留来源 ID、URI/请求信息、内容版本/摘要、事件时间、公开时间、接收时间、取得方式及质量状态。不存在的历史字段明确缺失。
5. 区分历史回填和实时录制。接收时刻只对真实录制成立，不能把今天回填的下载时间当历史可得时间。
6. 生成覆盖报告：事件数、独立事件组、连续时段、缺段/重复、粒度、延迟可信度及历史/实时差异，交给 02 和 08。

## 4. BTC 最小实例

**建议：**一条 BTC 成交/报价/可得深度通道，加一类带原文的官方宏观事件；初始候选为 FOMC 声明。前者提供交易时状态，后者提供异步语义；账户状态由 07 产生。若无法获得能支持假设的历史深度，明确改为可得的较粗微观代理并降低对应声明，或调整实验，不能假装拥有队列数据。

FOMC 每年例行事件有限，同一事件后的数百根 K 线不增加独立宏观事件数。数据窗口要根据可检验效果、事件覆盖和不确定性选择，不规定一个虚假的通用最少样本数。具体前向日期约束见 [BTC 实验](BTC-MVP.md)。

## 5. 失败如何观察

| 失败 | 可观测证据 | 处理去向 |
|---|---|---|
| 存在 API 但缺必要历史 | 时间范围/字段覆盖差异 | 调整来源或实验声明，不先训练弥补 |
| 新闻历史缺发布时间精度 | 只有日期或事后修订正文 | 02 明确延迟区间；不能支持分钟级时点论断 |
| 只有行情，没有成本/合约信息 | 环境无法计算现金流 | 07 的账户实验不能宣称经济有效 |
| 事件数量少或集中一个状态 | 覆盖报告和事件分组 | 08 限定统计结论；讨论补样本或换假设 |

## 6. 分阶段能力与证据

| 阶段 | 本环节实质内容 | 验证与推进条件 |
|---|---|---|
| 最小 MVP | BTC 微观＋一类宏观原文＋账户来源；历史/实时路径、覆盖与不确定性清单 | 能重取/定位原始记录；两种模态覆盖匹配实际实验，缺口显式进入验收 |
| 第二步：针对失败补强 | 若错误来自延迟/缺段，补相应数据；若机制需要新增信息，增加一条有明确假设的来源，例如宏观 vintage 或独立确认渠道 | 比较补入前后覆盖、时间可信度和下游增量；无增益来源可停用 |
| 第三步：跨状态与运行验证 | 检查更多事件/流动性状态，验证历史与实时字段一致、限流/断流恢复及来源变更 | 真实观测日志与覆盖报告支持目标时效；不能用插值掩盖断流 |
| 完整能力：可复用研究产品 | 可查询的数据目录、来源版本与可用性记录，按任务选择信息集及预算 | 新任务可以说明数据来处与限制；新增场所/付费源须有用途与授权，不以接入数量验收 |

## 7. 依赖与待定

02 决定哪些原始记录在某时点有效；03 判断文本和事件归属；07 决定必须具备哪些执行字段；08 判断样本能支撑多强的结论。待定项为场所、工具、历史范围、来源许可/预算和时效要求。其未定不阻止框架讨论，但不得在实际运行前隐式使用默认值。
