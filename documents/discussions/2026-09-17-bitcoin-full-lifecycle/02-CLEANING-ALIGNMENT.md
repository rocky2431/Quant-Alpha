# 02 清洗、历史版本与异步时点对齐

> **2026-09-17 当前讨论稿｜未批准实施。** [索引](README.md) · 上游：[01 接入](01-DATA-INGESTION.md) · 下游：[03 语义](03-ATTRIBUTION-SEMANTICS.md)、[04 表示](04-OPERATORS-REPRESENTATIONS.md)

## 1. 目的与输入输出

把原始数据转成在每次决策时确实可使用的观测，保留不确定性和历史版本。输入为 `RawRecord`、决策时间、市场规则和数据分区；输出 `AlignedRecord`、修复记录、缺失/新鲜度字段及版本映射。

清洗包含规则性错误处理；去噪是依赖任务的候选变换，不能默认删除异常行情。对文本的重复传播和冲突归并由 03 处理，对模型特征的冗余由 05 处理。

## 2. 时间字段与使用规则

| 字段 | 含义与限制 |
|---|---|
| `event_time` | 交易/经济事件实际发生时刻，不自动代表系统知道它 |
| `published_at` | 来源对外发布时刻；后续修订另建版本 |
| `first_observed_at` | 本系统实际首次收到该版本的时刻；历史回填可能不存在 |
| `processing_ready_at` | 解码、语义提取等完成，可供策略使用的时刻 |
| `usable_at` | 当前实验确定的可用时刻，需满足前述实际因果先后；历史缺失时附延迟假设 |
| `retrieved_at` | 本次取得数据的时刻，用于血缘，不能冒充历史接收时刻 |

决策时点为 `t` 时，仅从 `usable_at <= t` 的记录中按实体/字段选择当时适用的最新版本，并输出距上次更新的时间及过期状态。不能把未来公告向前插值。已知未来的**日程**可提前使用，未来的**发布内容**不能。

ALFRED 的历史版本查询有助于防止把修订数据带回过去，但取得哪一版、何时发布仍需进入记录。[官方版本说明](https://fred.stlouisfed.org/docs/api/fred/fred_vs_alfred.html)。

## 3. 具体处理步骤

1. 保存原始数据；校验单位、编码、时区、标识及交易字段关系。
2. 以来源记录标识和版本/内容判定原始重复，保留被合并记录的引用和接收信息。来源不同的相同报道不在此层全部删除。
3. 处理乱序、缺段和重复事件；可修复的错误生成新处理版本，无法确定的记录标记隔离，不补造价格/成交。
4. 为公告、宏观值和实体资料保留修订序列，建立当时可见版本视图。
5. 按真实可用时刻进行 as-of 对齐。不同频率分别聚合，窗口只含当时已完成的数据；当前未完成 K 线须使用不同字段名和训练语义。
6. 将缺失、新鲜度、数据龄和更新次数作为后续可用状态，不仅输出补齐后的数值。
7. 插补、缩放、滤波和离群阈值若要拟合，只使用允许的训练数据；应用到验证/未来时冻结拟合结果或遵守预定更新规则。
8. 为代表性决策生成“为什么这条信息此时可见”的可追溯证据。

## 4. BTC 具体例子

假设官方声明在 `T` 发布，系统在 `T+2s` 接收，结构化提取在 `T+8s` 完成。`T+5s` 的策略只能使用此前内容和“新文档待处理”的状态；`T+10s` 才能用新语义。微观数据若在 `T+10s` 之前已过期，必须同时显式暴露过期状态。

这是示意时间，不是已测延迟。历史无接收日志时，可以提出若干保守延迟情景比较结果，但不能把假设值标为测量值。纪要在其自身发布后进入，不得回填声明日；同一声明保持事件 ID，在后续多根 K 线上只是状态延续。

## 5. 失败、边界与反例

| 失败/容易误用的处理 | 观测或反例 | 处理原则 |
|---|---|---|
| 全样本缩放、居中滤波、整段分解 | 改变未来数据导致过去特征变化 | 将变换限制到训练/历史窗口，或明确其不可在线使用 |
| 删除极端价格/深度跳变 | 删除后回撤变小但真实清算事件消失 | 回查来源和市场事件；保留真实尾部，必要时附质量标记 |
| 无限前向填充 | 断流后指标仍看似平稳 | 加过期条件，07 对新开风险有明确处理 |
| 使用最终修订值 | 历史运行不能重现当时可见版本 | 修订链复原或标明不能使用该历史区间 |
| 随机插补遮盖停止交易 | 缺失与流动性状态有关 | 保留缺失机制，不将缺失视为随机噪声 |

双向 LSTM 若仅读取决策前完整历史窗口，不必然泄漏；若插补当前特征时读取决策后的数据，则泄漏。判断依据是实际信息边界。

## 6. 分阶段能力与证据

| 阶段 | 本环节实质内容 | 验证与推进条件 |
|---|---|---|
| 最小 MVP | 统一时间、原始去重、版本保留、因果对齐、缺失/过期标记；简单必要清洗 | 选定事件前后逐笔追溯；未来数据变化不影响已冻结的过去输入；接收未知明确标注 |
| 第二步：针对失败补强 | 对已发现的乱序、延迟偏差、修订或数据缺失补处理；必要时比较因果滤波/插补与原始通道 | 修复消除具体错误，并检验是否改善下游；不能只看曲线更平滑 |
| 第三步：跨状态与运行验证 | 在断流、来源改版、夏令时、极端行情和更长运行中检验一致性 | 历史/实时输入语义一致，故障恢复不引入重复动作或未来信息 |
| 完整能力：可复用研究产品 | 按任一研究版本恢复当时可见数据，比较处理变更影响，支持多频率任务 | 可解释每项修复及其适用边界；复杂去噪仅在有下游证据时保留 |

## 7. 相邻依赖与待定

需要 01 提供原始字段和覆盖；03 的提取耗时反向影响可用时间；04/05 的拟合范围必须遵守本环节时间规则；08 负责整条流程的隔离验证。待定为真实延迟、时点精度、最大数据龄和各类数据缺失时的操作策略，不能用一个通用超时覆盖所有来源。
