# 04 算子化、因子与特征表示

> **2026-09-17 当前讨论稿｜未批准实现算子或训练。** [索引](README.md) · 上游：[02 对齐](02-CLEANING-ALIGNMENT.md)、[03 语义](03-ATTRIBUTION-SEMANTICS.md) · 下游：[05 融合](05-FUSION-SELECTION.md)

## 1. 目的、输入与输出

把可用信息变成能够重算、组合和评价的数值或结构化表示。输入为 `AlignedRecord`、`EventEvidence` 和机制假设；输出 `FeatureSpec` 与带时间/版本的 `FeatureFrame`。因子既可以是人工表达式，也可以是学习得到的表征；表达式并不等于只能使用 OHLCV。

用户所说固定/静态流程指研究方式，不是说树模型在数学上是线性的。同源价格变换可以让模式更易被模型学习，但不会凭空产生外部信息；新增信息和改进表达需要分别做对照。

## 2. 一个算子必须说明什么

| 契约 | 内容 |
|---|---|
| 输入 | 字段、单位、来源、实体键、所需历史长度和质量状态 |
| 计算 | 确切公式/模型、参数、窗口方向、聚合与缺失规则 |
| 拟合 | 是否需要训练，允许的 `fit_scope`，权重/统计量版本 |
| 时间 | 输出可用时刻、计算延迟、是否依赖完成的时间桶、状态更新/重置规则 |
| 输出 | 名称、类型、单位、范围、缺失/置信字段、解释与已知边界 |
| 证据 | 对应原始/语义记录、实现版本、数值检查和机制假设 |

初期使用普通函数和现成算子即可，不要求先开发专用 DSL。Agent 可以提出表达式或实现候选，但实际执行需验证输入、单位、时间和数值结果。

## 3. 具体过程

1. 从机制提出表示需求，例如“事件内容相同但流动性状态不同，反应和可成交性不同”。
2. 先建立少量有明确含义的字段，不以自动生成数量为目标。
3. 对窗口、单位和状态定义契约；所有记录必须在决策时已可用。
4. 计算无拟合算子；需拟合的缩放、编码器、降维等仅使用相应训练分区。
5. 生成可追溯的特征快照，记录计算成本、缺失比例及分布。
6. 检查常数、除零、量纲、未来依赖、训练/实时差异；与小样本手算或来源数据核对。
7. 把候选交 05 做组合与增量验证，不因单独 IC 低直接删除。

## 4. BTC 最小表示示例

| 表示 | 定义建议 | 边界 |
|---|---|---|
| 短时收益/波动 | 对决策前已完成的价格窗口计算 | 窗口和收益单位固定；不可混入当前未来收盘 |
| 买卖价差 | `(ask - bid) / mid`，可转换为基点 | 缺报价/价差异常输出质量状态，不默认零成本 |
| 深度失衡 | 指定相同价格范围内 `(bid_qty - ask_qty) / (bid_qty + ask_qty)` | 分母为零时缺失；盘口范围与方向一致 |
| 主动成交方向统计 | 从可识别的成交方向滚动聚合 | 无法可靠识别时不冒充真实买卖发起方 |
| 事件变化/条件字段 | 03 的有证据语义，不直接附未来收益 | 数值编码和未知状态可追溯 |
| 事件龄/数据龄 | 当前时刻减对应可用时刻 | 区分原文发布龄、语义可用龄及盘口龄 |
| 语义与流动性交互 | 事件字段与价差/波动/深度状态的组合 | 交互假设先写清，再用开发数据检验 |
| 账户状态 | 持仓、可用资金、未完成订单等 | 由 07 的当时账户生成，不由最终 PnL 反推 |

这些例子说明 BTC MVP 已同时具有宏观/语义与微观结构。可学习编码器可以作为替代表示，但不是完成最小闭环的数量要求。

## 5. 常见失败与观测

表达式大量不同但输出几乎相同，提示重复搜索；跨年符号翻转，提示机制/状态或时间问题；训练特征正常而实时大量缺失，提示契约不一致；去噪后收益提升却只因抹除尾部，提示清洗污染；一个复杂特征仅在特定事件成立，则应分事件与状态检验，不能先宣布普遍 Alpha。

RL 生成因子表达式可参考 [AlphaGen](https://arxiv.org/abs/2306.12964)，其动作是表达式搜索，与交易开仓/仓位动作不同。采用因子搜索 RL 不构成交易 RL 验收。

## 6. 分阶段能力与证据

| 阶段 | 本环节实质内容 | 验证与推进条件 |
|---|---|---|
| 最小 MVP | 上述少量、带来源和时间的 BTC 特征；同一计算用于回放与前向；保留原始状态旁路 | 代表性事件可重算，未来输入变化不改过去结果，单位/缺失规则一致 |
| 第二步：针对失败补强 | 若语义或状态丢失，补一个针对性算子、历史窗口、条件交互或编码器；若冗余，合并表达式 | 修改的预期效果与消融一致，新增代价可接受；无增量候选被淘汰 |
| 第三步：跨状态与运行验证 | 检验不同波动/流动性/事件状态的表示稳定性、漂移、计算时效和实时一致性 | 特征不只对某段历史有效；在缺失/极端状态仍有明确语义 |
| 完整能力：可复用研究产品 | 带血缘与用途的算子/表征目录，支持组合、版本比较及必要的自动生成 | 每个候选有可执行契约和增量证据；更丰富的表示依据实际问题加入 |
