# Codex 第二轮评议：有条件同意双轨

2026-09-18，终轮。评议对象：[v0.1](../UNIFIED-PLAN.md)，行号以本轮读取版本为准。已读四份附录及[第一轮](codex-round1.md)。✅ 原始正文；🟡 二手、摘要或受限索引；❌ 未核实。无发布日期网页均以本日为核验日期；文内矛盾与反例均为本轮判断，不冒充论文结论。**共 32 项需修改的问题，重复位置合并计数。**

## A．有条件同意

同意“A 主线、B 有预算的比较支路”，不同意两套完整生产策略同时承诺四周交付。建议条件：

1. A 先用 BTC，ETH 作迁移；B 限一个标的类别、少量市场。B 工程工时暂限共享预算的 20%，前三个工程日核清历史覆盖、外部价格与录制成本；这是建议预算，不是实测工期。
2. 共用采集和账本接口，分别验收账户、规则及执行。B 特有缺陷只阻断 B；共享账本错误阻断两轨交易。
3. 预登记两轨候选数、试验数、费用、停止日期及选择规则；同一封存窗口的择优也计入检验。事件按共同冲击聚簇，禁止拿市场数充当独立样本。
4. 保留真实训练、完整产品及约定实盘要求；先解决日程冲突，不能自动把 LLM Agent RL 移出交付。A/B 同样须核实实际主体、账户和执行资格，不能只审 Polymarket。

**额外成本确实超出三处公式。** HIP-3 每个 DEX 有独立保证金、部署者设置和抵押品选择；还需外部行情的使用权限、时区／节假日／复权与汇率对齐、独立账户回放、预言机异常及退出验证。✅ [HIP-3 规范][hip]。复用 API 可省接入工作，不能证明这些成本很低；本轮也没有成本大于收益的实测证据，故不反对有限比较。

B 的实证线索值得保留，但被引用报告来自 **Blockworks Research，2026-08-03**，并非 Messari：614 个市场周末来自 68 市场、17 次闭市，设成交量及完整性筛选；84% 收敛来自另一组 100 次重开。🟡 [原报告索引正文][bw]（直接打开要求登录）。它支持研究假设，不保证新的样本、订单或净收益。

## C．必须补齐的三项

| 缺项 | 为什么必要／最小补法 |
|---|---|
| 资金—成本—延迟预算 | HL 原生基础 taker 单边4.5bp，往返已9bp，尚未计其他摩擦。✅ [费用][fees]。对实际订单规模测深度、成交率、滑点和端到端延迟分位数；按净优势随规模变化确定容量，不能用盘口总深度代替。 |
| 录制与研究资源账 | 官方非验证节点要求16 vCPU、128GB RAM，默认日志约100GB/日；28日约2.8TB是算术估算。✅ [节点][node]。列存储／带宽／保留期、试验次数及 GPU／token／人工时预算；B 达上限或关键数据缺失即暂停扩展。 |
| 部署者与抵押品边界 | 共享 HL 不消除独立 DEX、oracle、抵押品及停市结算风险。✅ [HIP-3][hip]。按部署者限总敞口，记录外部参考源失效／规则变化的停止与退出行为；减仓可行性也须验证。 |

## D．终局排序

1. **BTC 普通永续，ETH 后迁移**：最贴近完整训练—交易交付目标；优势未被证明。
2. **HIP-3 小范围会话支路**：共用接入且有可检验研究线索，上调至第二；仍需净执行证据。
3. **Polymarket 逻辑组合**：支付结构有价值，首期受多腿执行、数据与资格条件约束。

如果所有者坚持 BTC 单轨，我建议至少保留宏观语义、真实参数训练、三类对照及独立事件簇评价；资源允许时只录少量 HIP-3 参照，不建第二生产策略。

如果所有者接受双轨，第一个应该砍掉的是**全市场、全 HIP-4／Polymarket 同步录制与建模**；保留两轨受控比较，完整交付不缩水。

## E．给所有者的一句话

最容易高估的是“公开机制加共用引擎就能低成本得到可盈利对照”；最容易低估的是把真实训练、可信评价与连续实盘同时交付所需的数据、时间和执行接缝。
