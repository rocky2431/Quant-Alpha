# 项目分解与 UltraGoal 目标序列

**项目**：链上量化系统 — 机会发现 → 建模 → 仿真 → 执行开单，生产级
**底座决策**：NautilusTrader（用户 2026-09-07 确认）
**日期**：2026-09-07

---

## 零、边界：买什么，造什么

### NautilusTrader 提供（不重造）

事件溯源（消息总线边界捕获、per-run seq、cache 是投影不是真相源）｜确定性仿真测试（seed 可重放，pre-commit 强制）｜backtest / sandbox / live 共享同一 `NautilusKernel`｜执行对账（execution reconciliation）｜订单生命周期状态机｜数据目录（Parquet）｜Hyperliquid / dYdX / Lighter 适配器｜Rust 核心 + Python 控制面

**两个白捡的映射**：Nautilus 的 **backtest ≈ T1 重放**；**sandbox ≈ T3 影子**。保真度阶梯基本已在，缺的只有 T2 反应环境。

### 我们造的增量

1. **会计核心 spec + 三方对账**（不存在于任何公开架构）
2. **接缝扫描 + 候选登记簿**（假设生成器）
3. **m 通道特征层**（清算图/机制状态/会话状态/跨场所 basis）
4. **price 模块 + 天花板度量 + 泄漏探针**
5. **T2 反应环境**
6. **验证 gauntlet G0–G8**
7. **MPC / 结构化 RL 策略**
8. **Agent 编排层**（六个岗位，见第二章）

### ⚠️ 架构决定：会计核心是平行影子账本，不是引擎补丁

**不去改 Nautilus 的撮合引擎。** 会计核心消费同一事件流，独立算账，然后做**三方对账**：

```
会计核心 spec  ←→  Nautilus 账户状态  ←→  链上真值
        任意两方不一致 = 信号
```

三个理由：
- **避开 LGPL fork 路径**——增量以插件/策略/独立模块存在，不修改引擎本身
- 会计核心可独立测试，不被引擎实现细节污染
- **三方比两方强**：spec 错、引擎建模不符、场所改参数，三种故障可被区分

## 二、Agent 层的形状与约束

### 唯一组织规则

> **Agent 产出 = 提议。每条提议落到一个预注册的、机器可判定的验收上。Agent 不是任何验收的裁判。**

依据：模型、worker、检索内容、工具输出**不能创造或扩大权限**；**不得在缺少环境证据时报告成功**。

本项目的特殊优势：**存在真值预言机（链上状态）**，因此 agent 产出可被机械判真假。这是 agent 层在此安全的根本原因。

### 六个岗位

| Agent | 形状 | 产出 | 预注册验收 |
|---|---|---|---|
| **Spec 起草员** | native tool loop | 会计核心代码草稿 | **重放对账通过** |
| **漂移分诊员** | 事件触发 workflow | 定位漂移字段 + 补丁 | 补丁重跑对账通过才可合入 |
| **接缝提议员** | 单次调用／有界循环 | 候选（含接缝类型、零假设、证伪脚本） | **schema 校验**：缺零假设或缺预注册阈值哈希 → 程序拒收 |
| **证伪执行员** | coded workflow，agent 只在两端 | 跑测试、写结论 | 阈值在看数据前提交并哈希锁定 |
| **场所监控员** | 定时 | 文档/公告/链上参数变更提示 | 只提示，转给分诊员 |
| **实验归因员** | 单次调用 | 解释 gauntlet 矩阵变化 | 纯咨询，**永不成为闸门** |

### 硬禁止

Agent 不得：进入下单决策路径｜评判策略是否有效（那是 gauntlet）｜选择或修改阈值｜绕过 conformance 改 spec｜接触私钥或资金路径｜以「另一个模型认可了」作为通过依据。

### 信任边界

场所文档、治理论坛、changelog 是**外部不可信内容**。它们可以促成 spec 变更提议，**不能授权变更**。唯一的授权者是对账通过。**预言机即防线。**

## 三、UltraGoal 目标序列

每条目标三元组：**Intent**（可改进的结果）／**Anchor**（机器可判定的完成条件，尽量是一条命令）／**Boundary**（范围约束）。

### 轨道 A — 数据与状态平面

**A1 · 5 秒 L2 录制**　`无依赖 · 第 0 天启动`
- **Intent**：建立不可追补的行情基座，使 funding/premium 可被逐字段校验
- **Anchor**：`make verify-recording` — 连续 7×24h 缺口率 <0.1%；从录制数据重建的 `impact_bid_px`/`impact_ask_px` 与同时刻 API `metaAndAssetCtxs.impactPxs` 差 ≤1 tick，覆盖 ≥6 个标的（主 perp 3 + HIP-3 3）
- **Boundary**：只读只录；不签名不下单；不改 Nautilus 引擎

**A2 · HL 节点与全局状态**　`← A1`
- **Intent**：拿到全局持仓而非公网 API 的 34.9% 抽样
- **Anchor**：`make verify-node` — 本地 `--serve-info` 的 `clearinghouseState` 与公网 API 对 100 个随机账户逐字段一致；由 `compute-l4-snapshots --includeUsers` 聚合的全网 OI 与 `metaAndAssetCtxs.openInterest` 差 <1%
- **Boundary**：只读；不签名

**A3 · 接入 Nautilus 数据平面**　`← A1`
- **Intent**：复用事件溯源与数据目录，不自造
- **Anchor**：`make verify-catalog` — 录制数据经 Nautilus DataCatalog 回放，生成的 `OrderBookDeltas` 序列与原始录制字节级等价；确定性仿真测试（同 seed 两次运行）事件序列哈希一致
- **Boundary**：**不 fork Nautilus 引擎**；增量以插件/策略/独立模块形式存在（LGPL 合规）

### 轨道 B — 机制规格与校验

**B1 · 会计核心 spec**　`← A2`　`agent: spec 起草员`
- **Intent**：把 PnL 真正依赖的机制写成可执行代码
- **Anchor**：`make test-accounting` — 属性测试通过；对 20 个已知历史清算事件算出的 `liq_price` 与链上 `liquidationPx` 差 ≤1 tick、触发区块差 ≤1；**覆盖 cross/isolated、margin tier 分档、以及普通 perp 与 HIP-3 两套不同的 funding 公式**
- **Boundary**：不含撮合/队列位置/部分成交顺序；agent 可起草，但**必须过 B2 才算完成**

**B2 · 三方对账 + 每日 CI**　`← A1, A3, B1`　★关键闸门★
- **Intent**：让机制漂移可被自动检测，而不是等亏钱才发现
- **Anchor**：`make conformance --months 3` — 三方一致（会计核心 vs Nautilus 账户状态 vs 链上真值）；funding payment 逐笔对齐（容差 = 最小计价单位）；清算触发区块差 ≤1；失败非零退出；已接入每日 CI 且有告警通道
- **Boundary**：只对账 spec 内字段；撮合相关不对账
- **停止条件**：**4 周内 Anchor 不通过 → 整条路线停**。这已是最简单场所、最小机制子集、最公开规格。

**B3 · 漂移分诊 agent**　`← B2`
- **Intent**：CI 变红时，把「哪个字段漂了」变成可执行的修复提议
- **Anchor**：注入 3 个人造漂移（改 impact notional、改 MMR、改 clamp 边界），分诊 agent 在无提示下正确定位字段 ≥2/3，且其提议的补丁重跑 `make conformance` 通过
- **Boundary**：agent **只提议**；补丁必须过 B2 才能合入；agent 无主分支写权限

### 轨道 C — 机会发现

**C1 · 接缝扫描 + 候选登记簿**　`← B1`　`agent: 接缝提议员`
- **Intent**：让机会发现可重复、可审计、可淘汰
- **Anchor**：`make seams` 输出候选清单，每条**强制**含 5 项——spec 字段引用／接缝类型（6 类之一）／零假设／可运行的证伪脚本／**预注册阈值的哈希**；缺任一项 → 程序拒绝入库。登记簿状态机（候选→证伪中→否决／确认→上线→退役）有测试
- **Boundary**：只输出假设，不输出策略；agent 提议，**schema 校验裁决**

**C2 · 第一批证伪**　`← C1`　`agent: 证伪执行员`
- **Intent**：淘汰假机会，同时验证证伪流水线本身能用
- **Anchor**：石油永续 funding 对 WTI/Brent 期货曲线 roll yield 的归因回归完成，按**预注册阈值**给出「残差显著／不显著」结论（两种结论都算达成）；≥5 条候选走完完整状态机
- **Boundary**：只做归因不建策略；**阈值必须在看数据前提交并哈希锁定**

### 轨道 D — 建模

**D1 · 泄漏探针 + 天花板度量**　`无依赖 · 可与 A/B 全程并行`
- **Intent**：判定现有管道健康度与信息天花板，把「要不要换模型」从争论变成算术
- **Anchor**：`make probe` — 注入 forward return 后 IC 提升超预注册阈值（否则判定为**管道故障**并停止一切新算法工作）；产出互信息估计的 R² 上界与 `T_crit` 数字；两者进 CI
- **Boundary**：在现有 Qlib pipeline 上做，不改策略
- **备注**：成本几天，且能否定一大片下游工作。**优先级最高之一**

**D2 · m 通道特征层**　`← A2, B1`
- **Intent**：接入 CEX 结构上拿不到的输入
- **Anchor**：清算图、premium/impact 机制状态、会话状态（距重开时长／bounds 剩余空间／重锚定计数）、跨场所 basis 可作为特征取用；**每个特征有 point-in-time 保证**（回测取到的值 = 当时可得的值，有测试证明）
- **Boundary**：只做特征，不做模型

**D3 · price 模块**　`← D1`
- **Intent**：可替换、独立记账的价格分布
- **Anchor**：输出**分布**（非点估计）；PIT/CRPS 校准达预注册阈值；预测器指标与策略指标**分离存储**，可独立回答「预测变好了还是规划变好了」
- **Boundary**：输出分布，不做决策

### 轨道 E — 策略与仿真

**E1 · T1 重放环境**　`← A3, B2`
- **Intent**：可信的单边执行仿真
- **Anchor**：重放一条历史真实成交序列，环境算出的账户变动与链上一致（≤最小计价单位）；**撮合假设写进 manifest**并随结果一起产出
- **Boundary**：对手冻结；建立在 Nautilus backtest 上

**E2 · 自适应基线库**　`← E1`
- **Intent**：让任何 RL 结论有意义
- **Anchor**：每个 spec 配一个自适应基线；**基线参数经优化且有优化记录**（防稻草人）；基线在 T1 上有正期望
- **Boundary**：规则式，不含学习

**E3 · CTA 通路**　`← D2, E1`
- **Intent**：传统方向性策略也能跑，且能吃到 m 通道特征
- **Anchor**：一个 CTA 基线策略在 Nautilus backtest 跑通并能取用 D2 特征；通过 D1 的泄漏探针与天花板度量
- **Boundary**：与 MPC 路线**共用同一 gauntlet**，不开后门

**E4 · MPC / 结构化 RL**　`← D3, E2`
- **Intent**：在被校验过的机械动力学上做有限期规划
- **Anchor**：跨 ≥10 随机种子，相对 E2 基线的超额落在种子方差之外；QP 求解 p99 延迟 < 预算
- **Boundary**：只调骨架参数（风险厌恶／偏斜／执行比例／报价深度）；**禁止**端到端方向预测、LLM 决策、学习式 sizing、学习型世界模型

**E5 · 证伪审计（G5）**　`← E4`　★守门员★
- **Intent**：排除工作流泄漏
- **Anchor**：在零可预测性合成数据上，**整条流水线**（非只策略）的收益 95% CI 覆盖 0
- **Boundary**：不改策略，只审计。不通过 → 前面全部作废

**E6 · T2 反应环境**　`← E1`
- **Intent**：估计反身性溢价
- **Anchor**：响应 agent 复现历史上簿价偏移的收敛速度分布（KS 检验不拒绝）；产出按下单规模分层的 Δ(T1,T2)
- **Boundary**：**校准目标必须链上可观测**；校准不过 → T2 结果不得用于决策

### 轨道 F — 执行、风控与运维

**F1 · 执行层 + 对账**　`← A3`
- **Intent**：生产级下单
- **Anchor**：sandbox 模式下 100% 订单可对账；拒单／超时／部分成交／reduce-only 路径有测试；Nautilus execution reconciliation 通过
- **Boundary**：sandbox，**不提交真实订单**

**F2 · 风控 + 私钥隔离**　`← F1, B1`
- **Intent**：可控的真钱暴露
- **Anchor**：事前限额检查覆盖 spec 全部约束（订单名义额上限／距清算价余量／discovery bounds 剩余空间／单市场与总敞口）；kill switch 三级（降规模／只减仓／全平）演练通过；**有测试证明策略进程无法取得私钥**
- **Boundary**：权限最小化；签名服务独立进程

**F3 · T3 影子运行**　`← E4, F2`
- **Intent**：真实世界机械层地面真值，不需要资金
- **Anchor**：连续运行 ≥4 周且**跨越至少一次高波动事件**；机械层预测（成交／funding／距清算价）偏差 100% 可归因到具体 spec 字段
- **Boundary**：listen-only

**F4 · 小额真钱**　`← E5, F3`
- **Intent**：首次真实暴露
- **Anchor**：实盘 vs 影子偏差可归因；分层放量规则**由代码强制**（非人工纪律）；连续 N 日无不可归因偏差
- **Boundary**：硬性资金上限，代码强制

**F5 · 运维**　`← F3`
- **Intent**：长期可运行
- **Anchor**：节点追块延迟告警；任一事故可由事件流完整重放；**高波动事件下的降级路径演练通过**（限速劣化、节点落后、行情缺口三种场景）
- **Boundary**：—

## 五、给 UltraGoal 的备注

- 每条 Anchor 已写成命令或可判定条件。若某条在你的 UltraGoal 里需要单一 `make` 目标，按上表的 `make xxx` 直接建。
- **B2 的停止条件是整个项目的第一个真实决策点**，建议作为独立里程碑而非普通目标。
- 阈值预注册（C1/C2/D1/D3）**必须由代码强制**：阈值文件在测试运行前提交并哈希锁定，测试脚本校验哈希。这是防 p-hacking 的机制化手段，不能靠约定。
- Agent 相关目标（B1/B3/C1/C2）的 Anchor **都不由 agent 判定**——这是本项目 agent 层安全性的全部依据。
