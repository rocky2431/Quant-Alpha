### 3.2 机制就是套利结构本体（官方文档 docs.trade.xyz）🟡

- **External session（标的开市）**：oracle = external price = 真实市场价
- **Internal session（标的休市）**：**external price 冻结在收盘价**；oracle 改用基于 HL 自身订单流的内部机制继续推进
- **Discovery bounds**：mark price 被限制在参考价 ±(1/最大杠杆) 内（WTI 20x → ±5%；SP500 50x → ±2%），带**棘轮式重锚定**（WTI 最多 2 次，之后硬顶）。**落在边界外的清算价在边界生效期间不会被清算。**
- **重开时 oracle 回归外部价，全部计数器 reset**
- relayer 每约 3 秒广播 oracle / mark / external 三个价格；oracle updater 地址公开可监控

**本质**：休市期间的 HIP-3 股票永续 = **一张结算日为下次开盘、结算价为重开 oracle 价的定期期货**。

### 3.3 收敛已被独立测量（Messari，2026-08-03，614 个 market-weekend 样本）🟡

- **84% 的重开在 5 分钟内回到 oracle 的 10bp 以内，89% 在 15 分钟内**

**这是决定性的**：结算是**快速、可靠、机制强制**的，不需要预测；而信息含量随跳幅单调上升。

原因是 clamp 造成的**死区**（官方公式）：

```
funding_8h = P + clamp(0.0001 − P, −0.0005, +0.0005)
```

当 8 小时 premium 落在 **−4bp 到 +6bp** 之间时，funding **恒等于 0.01%/8h，与真实基差完全无关**。主流币约一半时间，carry 交易者拿的不是基差补偿，而是那个固定的利率成分。

## 五、RL / MPC 的确切位置

### 5.1 为什么你过去的尝试全部失败：你一直在做纯 p 的问题

把状态拆开：
```
s = (p, m)
p = 外生价格   → 转移不可知 → 用最好的预测器，且必须承认它有信息天花板
m = 机械状态   → 转移是【已发布的公式】，且【依赖你的动作】
```

- **Qlib / 随机森林 = 预测 p。** 而 Alpha158 是纯价量的 158 个因子、窗口封顶 60 天、无基本面无舆情。Qlib 官方 benchmark（CSI300+Alpha158，20 种子）🟡：**Linear IC 0.0397 / 年化 6.92% 打赢 Transformer IC 0.0264 / 年化 2.73%**，参数量跨 3–4 个数量级全部挤在 IC 0.02–0.05。Gu-Kelly-Xiu 也写了"Shallow learning outperforms deeper learning"。**这是信息天花板。**
- **FinRL / FinGPT = 在外生 p 下做 model-free 配置。** 但这里有个判别性实验（FinRL GitHub #1248, 2024-06）🟡：**把未来 1/2/3/5 日收益直接泄漏成特征，A2C 依然学不出比 buy-and-hold 更好的东西**。项目负责人回复"the FinRL library is extremely poorly maintained"。配套还有基准口径偏差（agent 交易复权价而基准用纯价格指数 `^DJI`，**仅此一项值 +1.92%/年、8 年累计 +16.4%**，方向恰好美化 agent）、复现不出自己的论文、疑似前视偏差。
  → **FinRL 的"效果不好"测量的是框架，不是市场。它对市场没有诊断信息量。**

**你从来没有做过 m 这条通道。** 而 m 恰恰是链上给你、CEX 给不了的。

### 5.2 为什么"上 Dreamer/MuZero"是错的

**FinPILOT（arXiv:2605.12653）的结构论证** 🟡：在 **price-taker** 假设下价格外生、奖励是配置和实现收益的闭式函数 → **世界模型退化成一个价格预测器**。"model-based RL 做组合管理" ≡ "预测器 + MPC"，**一比特信息都不增加**。

叠加 **Wang et al. 2019 的 dynamics bottleneck** 🟡：用**学到的**动力学时 MBRL 停在一个远低于用 **ground-truth** 动力学时的平台，且**加数据不改善**。

→ 盲目上世界模型 = 继承信息天花板 + 额外买入一层 rollout 复合误差。

**但 FinPILOT 的前提是 price-taker，而 HIP-3 会话结构不是**：
- **终局条件是机制强制的**（重开时 oracle 回归 external price），不是预测出来的
- **discovery bounds 是硬状态约束**，你的仓位必须遵守，且边界内不会被清算
- **funding 逐小时按公开公式累积**，路径依赖且依赖你的动作
- **清算价由公开公式给出**（`liq_price = price − side × margin_available / position_size / (1 − l × side)`）✅，且 API 直接返回 `liquidationPx`

这是一个**有限期、终局已知、带硬约束、部分外生**的序贯决策问题。**这正是 MPC 的定义域。**

### 5.3 证据支持的确切形态

| 工作 | 结果 | 形态 |
|---|---|---|
| **MPC 执行**（含 Bertsekas，arXiv:2603.28898）🟡 | schedule shortfall 降低 **40–50%**；原文明说"**It is free of any market dynamics modelling**" | 已知机械规则 + 每步一个快速 QP |
| **结构参数化 RL**（Wang/Gao/Li, *Finance and Stochastics* 2026）🟡 | 用 Almgren-Chriss 闭式解参数化策略与值函数 → 参数极少 → 有线性收敛证明 → **同时打败 plug-in 经典控制与深度 model-free SAC**（后者不稳定） | 解析解做参数化骨架 |
| **Hendricks & Wilcox** 🟡 | RL 只调 AC schedule 的执行比例 → IS 改善 4.8–10.3% | RL 只调经典模型的少数参数 |
| **Alpha-AS**（PLOS ONE 2022）🟡 | RL 只调 Avellaneda-Stoikov 的风险厌恶与偏斜，**不直接出价**，基准是 GA 调优的 AS → 显著胜出 | 最坏退化回 AS |

**共同形态一句话：把确定为真的机械约束写死，把不确定的价格交给预测器。前者是免费的午餐，后者是把误设风险请进门。**

**反面警示**：Gašperov 综述 🟡 显示 22 篇 RL 做市论文 **22/22 全部报告正面结果**、只有 18% 用了 AS/GLFT 基线；Solovyev(2019) 的唯一一次对比中**自适应 Almgren-Chriss 打败了每一个 RL 配置**。→ **基线必须是自适应的、公平实现的，否则你测的是"自适应打败非自适应"，跟 RL 无关。**

```
│           动作：报价深度、每档规模、仓位迁移、撤单时机           │
│           不含：端到端方向预测、LLM 决策、学习式 sizing         │
│           sizing 用规则式（分数 Kelly / σ_target）             │
├──────────────────────────────────────────────────────────────┤
│ L1 环境   T1 重放（真实簿 + 真实 funding + 真实清算规则，对手冻结）│
│           T2 反应（注入校准过的响应 agent，校准目标须链上可观测） │
│           T3 影子（实时 listen-only，不提交）                   │
├──────────────────────────────────────────────────────────────┤
│ L0 状态   Hyperliquid 自建非验证节点                            │
│           `periodic_abci_states`（每 10,000 块）                │
│           `compute-l4-snapshots --includeUsers`（L4 全簿）      │
│           `--serve-info`（本地 info server，官方称可缓解限速）    │

│           + S3 `node_fills_by_block` 历史回补（requester-pays）  │

```

**为什么必须自建节点** 📊：公网 API 限速 1200 权重/分钟、`clearinghouseState` 权重 2 → 600 账户/分钟，扫完 4.5 万地址要 **75 分钟/IP**；实测按权益 top 2,498 个账户只还原了全局 OI 的 **34.9%**。**公网 API 做不了实时全局状态。** 节点要求 16 vCPU / 128GB RAM / 500GB SSD，默认约 100GB 日志/天（成本未估算 ❌）。

**已验证可用的关键端点** 📊：
- `clearinghouseState` **直接返回 `liquidationPx`**（无需自算）、`entryPx / szi / marginUsed / leverage / cumFunding`
- **`{"type":"liquidatable"}`**（官方 API 文档未收录但实测存在）——直接给出当前可被清算的仓位
- `maxMarketOrderNtls` —— 市价单名义额上限，直接约束清算单规模
- `metaAndAssetCtxs` —— markPx / midPx / **oraclePx** / premium / funding / openInterest / **impactPxs**

## 八、风险与会推翻结论的证据

| 风险 | 说明 |
|---|---|
| **石油 funding = backwardation** | 若第 1 步显示无残差，3.4 节作废。**这是最大的单点风险** |
| **HIP-3 深度未测** | ❌ 本次未测量 HIP-3 各市场的订单簿深度。$3.7B OI 不等于单一策略能跑多大。**必须先测再定资金规模** |
| **可观测性是选择不是属性** | Aster 的核心卖点是 Hidden Orders + ZK 隐藏仓位/PnL，**官方定位明确是防 liquidation hunting**。若行业向隐私迁移，状态可观测的前提消失 |
| **实测在清淡日做的** | 所有速率、还原率、深度实测均在 2026-09-07 低活跃时段。**10/10 那种事件中 API 限速、节点追块能力都可能显著劣化——而那正是最需要它工作的时刻**，今天无法验证 |
| **清算热图已商品化** | Hyperdash / GoldRush / CoinPerps 已有生产级产品。差异化不能在显示层 |
| **mark price 构成公式不完整** | ❌ 官方只给定性描述（外部 CEX 价 + 自身盘口状态），未找到完整加权公式。这是级联/边界模拟的实质不确定性来源 |
| **HIP-3 是新机制** | 2026 年才出现，规则可能变更（deployer 可自定义 oracle；discovery bounds 参数可调） |

**会推翻整个结论的**：第 1 步无残差；第 2 步显示管道坏了（则先修管道）；第 6 步证伪审计未通过；或 HIP-3 深度测出来远小于 OI 暗示的规模。

## 九、一句话总结

**不要再往 Qlib/FinRL 那条路上加模型——那是信息天花板加一个坏掉的框架。链上唯一给你、而 CEX 给不了的东西，是"机制本身是已发布的代码"：HIP-3 股票/商品永续在标的休市时冻结外部价、用 discovery bounds 硬约束 mark、并在重开时强制结算回 oracle——84% 在 5 分钟内收敛到 10bp 以内。把 RL 用在这个已知的机械动力学上做有限期规划，而不是用它去预测价格。第一件事：证伪石油 funding 只是 backwardation。**
